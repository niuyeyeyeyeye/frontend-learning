## 二、一句话理解 useEffect

> **useEffect = "组件渲染完之后，要额外做的事"**

什么叫"额外的事"（副作用）？
- 改 `document.title`（浏览器标签）
- 开定时器 / 发请求 / 加事件监听 / 存 localStorage
- **反正不是"画 UI"的事**

**为什么不能直接写在组件函数里？** 因为组件函数每次渲染都会重新执行 —— 你直接写 `setInterval` 就会每次都开一个新定时器（越来越快）。

## 三、依赖数组的三种情况（必须背下来）

| 写法 | 执行时机 | 用在哪 |
|---|---|---|
| `useEffect(() => {...})` | **每次渲染都执行** | 几乎不用（容易死循环） |
| `useEffect(() => {...}, [])` | **只在挂载时执行一次** | 初始化：请求数据、监听事件 |
| `useEffect(() => {...}, [count])` | **count 变化时执行** | 依赖某个状态的副作用 |

### ⭐ 依赖数组的核心原则

> **effect 里"用到"了什么 state/props，就必须把它写进依赖数组。**

- 写**少**了 → **闭包陷阱**（读到旧值，你 Day4 学过闭包）
- 写**多**了 → 不必要的重复执行（甚至死循环）
- 写了**对象/数组/函数** → 每次都新引用 → 每次都执行（需要 useMemo/useCallback，Day5 讲）

## 四、清理函数（今天最重要的一半）

```tsx
useEffect(() => {
  const id = setInterval(() => { ... }, 1000)

  return () => clearInterval(id)   // ← 清理函数
}, [])
```

**清理函数什么时候执行？**
1. 组件**卸载**时
2. **下一次 effect 执行之前**（依赖变了 → 先清理旧的，再跑新的）

**必须写清理函数的东西**：定时器、事件监听、订阅、请求取消、WebSocket。

### 三个最常犯的错

| 错误 | 后果 |
|---|---|
| 定时器没 `clearInterval` | 多个定时器叠加，速度越来越快 + 内存泄漏 |
| 事件监听没移除 | 监听器越积越多，组件卸载后还在执行 |
| **移除监听时用了新的函数引用** | `removeEventListener('resize', () => {...})` **移不掉！** 必须存变量，用同一个引用 |

## 五、⚠️ 关于 StrictMode 下 effect 执行两次（别慌）

你可能会发现：**组件挂载时 useEffect 执行了两次**。

这不是 bug —— 是 React 在**开发环境**故意做的检查（帮你提前发现"副作用没清理干净"的问题）。
- 生产构建（`npm run build`）里只执行一次
- 你可以用"定时器叠加"那个演示验证：如果清理函数写对了，活跃定时器数量始终是 0 或 1

## 八、顺便：你 Day3 练习 2 的一个小隐患

你写的是：

```tsx
const visibleTodos = todos.filter((n)=>
  filter==='done'?n.done===true:filter==='active'?n.done===false:n
)
```

能工作 ✅，但最后一个分支返回的是 **`n`（对象本身）** —— 它靠"对象一定是真值"这个隐含假设才成立。
如果哪天数据里出现 `null`，就会出错。**更清楚的写法**：

```tsx
const visibleTodos = todos.filter((t) =>
  filter === 'all' ? true : filter === 'done' ? t.done : !t.done
)
```

> 这条经验：**filter 的回调应该明确返回 true/false**，别依赖"真值/假值"的隐式转换。
