## 三、核心概念 1：路由就是一张对照表

```tsx
export const routes: RouteObject[] = [
  {
    path: '/',
    element: <RootLayout />,          // ⭐ 外壳，里面必须有 <Outlet />
    children: [
      { index: true, element: <Home /> },        // /
      { path: 'about', element: <About /> },     // /about
      { path: '*', element: <NotFound /> },      // 兜底
    ],
  },
]
```

**URL 变了 → React 去表里查该渲染谁 → 把 `<Outlet />` 那块换掉。整页不刷新。**

这就是 SPA（Single Page Application）：服务器只给了一个 `index.html`，之后全是 JS 在换内容。

### ⭐ 加一个页面 = 加一个文件 + 加一条路由

不需要改任何已有页面。这条是路由最大的价值，也是面试里"你怎么组织项目"的答案。

## 四、核心概念 2：三条铁律

### 铁律 1：站内跳转只用 `<Link>` / `<NavLink>`

```tsx
<a href="/day7/users">     ❌ 整页重载，应用重启，所有 state 清空
<Link to="/day7/users">    ✅ 客户端跳转，只换组件
```

**自己验证**：看页面右上角「本次启动：xx:xx:xx」。
用 `<a>` 跳回来它变了（应用重启），用 `<Link>` 永远不变。

> 这个坑特别阴：开发时 `<a>` 也"能跳"，看起来没问题 —— 但它把你的整个应用重启了一遍。

### 铁律 2：切路由 = 卸载 + 挂载（不是"藏起来"）

从 A 页切到 B 页：A 页**卸载**（`useEffect` 的清理函数会跑），B 页**挂载**，A 页的 state 全部消失。

→ 想在页面之间保留状态：放进 URL（`?q=xx`）、Context、或 store（Day8）。
→ `01-路由基础与Link.tsx` 的「实验 B」有计数器可以亲手验。

### 铁律 3：路由表只写在一个地方

`src/router.tsx`。组件只负责"我这页长什么样"，不关心"我怎么被访问到"。

## 五、核心概念 3：动态路由（一个组件服务无数个 id）

```tsx
// 路由表
{ path: 'users/:id', element: <UserDetail /> }

// 组件里
const { id } = useParams()     // 访问 /day7/users/2 → id 是字符串 '2'
```

⚠️ **`useParams` 拿到的永远是字符串。** `/users/2` → `{ id: '2' }`，不是 `{ id: 2 }`。
（所以我在 `UserDetail` 里用 `String(u.id) === rawId` 比，直接 `===` 会永远不等。）

⚠️ 另一件事：从 `/users/1` 点到 `/users/2`，**组件不会重新挂载**，只会重新渲染。
所以如果你在 `useEffect(..., [])` 里请求过一次数据，切到 `/users/2` 时**不会再请求**。
正确写法是依赖数组里写 `[id]`。（Day9 做请求时会再撞一次）

## 六、核心概念 4 & 5：useNavigate 和"URL 当状态源"

```tsx
const navigate = useNavigate()
navigate('/day7/users')                 // 跳过去
navigate(-1)                            // 后退一步
navigate('/day7/basics', { replace: true })   // 替换历史记录（后退回不去）
```

```tsx
const [searchParams, setSearchParams] = useSearchParams()
const q = searchParams.get('q') ?? ''
setSearchParams(next, { replace: true })   // 打字时用 replace
setSearchParams(next)                      // 翻页时用 push
```

### ⭐ 一句话原则：能用 URL 表达的状态，就别藏在 useState 里

| 状态 | 该放哪 |
|---|---|
| 搜索词、页码、筛选条件、当前 tab | **URL**（刷新不丢、能分享、能后退） |
| 表单里正在输入的内容、loading、弹窗开关 | `useState` |
| 登录用户、主题 | Context / store |

`/day7/navigate` 里那个「搜索 + 分页」就是完整例子，**动手验三件事**：
① 刷新条件还在 ② 复制地址到新标签页能复现 ③ 后退能回上一页

## 七、核心概念 6：嵌套路由 + Outlet

```
RootLayout("/")              ← 顶部导航
 └─ Day7Layout("/day7")      ← 今天的子导航       ← 你已经在用嵌套了
     └─ SettingsLayout       ← 设置页外壳（第 3 层）
         └─ profile / security
```

**父路由的组件里必须写 `<Outlet />`**，子路由才有地方渲染。

| 概念 | 是什么 | 忘了会怎样 |
|---|---|---|
| `<Outlet />` | 子路由的出口 | 地址对了，但页面只有外壳、内容空白 |
| `index: true` | 父路径本身就是这个页面 | `/day7/nested` 显示空 |
| 子路由 `path` 不加前导 `/` | `'profile'` 而不是 `'/day7/nested/profile'` | 父子关系断开，匹配不上 |

## 十、FAQ：你大概会撞上的 4 个报错

| 现象 | 原因 | 怎么修 |
|---|---|---|
| 地址对了，但页面只有外壳/空白 | 父组件忘了 `<Outlet />` | 在父组件 JSX 里加 `<Outlet />` |
| 控制台 `No routes matched location "/xxx"` | 路由表里没这条 | 加一条，或加 `path: '*'` 兜底 |
| 子页面 404 | 子路由 `path` 写了前导斜杠 | 去掉 `/`，写相对路径 |
| `useNavigate() may be used only in the context of a <Router>` | 组件不在路由树里 | 检查它是不是被渲染在 `RouterProvider` 里面 |

> 部署时还有一个经典问题：刷新 `/day7/users/2` 得到服务器 404 —— 因为服务器没有这个文件。
> 解决：服务器配 history fallback（Nginx `try_files $uri /index.html`），或改用 `createHashRouter`。
> **这个知识点以后 Day11 部署会用到，现在先记着"这不是 bug，是部署配置"。**
