## 四、核心概念 1：任何一个接口都有 **4 种状态**

```
loading（正在拿）→ error（拿失败）→ empty（拿到但是空）→ success（有数据）
```

新手只写第 4 种。这就是线上"白屏"和"转圈卡死"的来源。

| 状态 | 该长什么样 | 常见错误 |
|---|---|---|
| loading | 骨架屏 / 转圈 | 让用户对着空白猜 |
| error | **原因 + 重试按钮** | 只写"加载失败" |
| empty | "还没有内容" + 引导动作 | 当成错误提示，用户以为系统坏了 |
| success | 真数据 | — |

**最容易犯的**：只判断 `data.length > 0`，忘了 loading 时也是 0 → 会先闪一下"暂无数据"。

## 五、核心概念 2：axios 和 fetch 的差别（面试常问）

| 要做的事 | fetch | axios |
|---|---|---|
| **4xx / 5xx** | ❌ **不报错**，要自己 `if (!res.ok)` | ✅ 直接 reject，进 catch |
| JSON 解析 | ❌ `await res.json()` | ✅ 自动（`res.data`）|
| 超时 | ❌ 自己写 AbortController + 定时器 | ✅ `timeout` 配置 |
| 统一加 token / 统一报错 | ❌ 每个调用点各写一遍 | ✅ 拦截器一处搞定 |

**第一条最关键**：`fetch('.../404')` 会 **resolve**，你写 `fetch().then(r => r.json())` 拿到的是 404 的错误 JSON，还以为成功了。

## 六、核心概念 3：错误要分类（catch 里不能只有一句"出错了"）

| 情况 | `err.code` | `err.response` | 提示什么 |
|---|---|---|---|
| 断网 / 跨域 | `ERR_NETWORK` | **无** | 网络异常 |
| 4xx | `ERR_BAD_REQUEST` | 有，status 4xx | 401 登录过期 / 404 不存在 |
| 5xx | `ERR_BAD_RESPONSE` | 有，status 5xx | 服务器出错，稍后再试 |
| 超时 | `ECONNABORTED` | 无 | 请求超时 |
| 主动取消 | `ERR_CANCELED` | 无 | **不用提示**（不是错误）|

**判断顺序**：先看 `err.code`（网络/超时/取消都没有 response），再看 `err.response.status` 分 4xx/5xx。

`toFriendlyError()` 就是按这个顺序写的，在 `mock/mockApi.ts` 里，可以直接搬到自己项目。

## 七、核心概念 4：拦截器（封装的核心价值）

```ts
const http = axios.create({ baseURL: '/api', timeout: 10000 })

// 请求前：自动带 token
http.interceptors.request.use((config) => {
  const { token } = useAuthStore.getState()     // 从 store 读（Day8 的知识）
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config                                  // ⚠️ 忘了 return → 请求变 undefined
})

// 响应后：剥 data + 统一错误
http.interceptors.response.use(
  (res) => res.data,                             // 调用方直接拿数据
  (error) => {
    if (error.response?.status === 401) useAuthStore.getState().logout()
    return Promise.reject(error)                 // ⚠️ 忘了 reject → 错误被吞，永远 loading
  },
)
```

> 注意 token 存在 **Zustand store** 里 —— 因为拦截器是模块级的，拿不到组件里的 `useState`。
> 这正是 Day8 说的"状态住在 React 之外"。

## 八、⭐ 核心概念 5：竞态与取消（今天唯一真正新的一节）

### 竞态是什么

```
你点「搜索 A」（慢，900ms），紧接着点「搜索 B」（快，120ms）
   → B 的结果先回来，屏幕显示 B
   → A 的结果迟到，把 B 覆盖掉 ← 💥
用户明明搜的是 B，看到的是 A 的结果。
```

### 治法只有一句：**每次发新请求前，把上一个 abort 掉**

```tsx
useEffect(() => {
  const controller = new AbortController()

  api.get('/posts', { signal: controller.signal })    // ① signal 塞给请求
    .then((res) => { setData(res.data); setLoading(false) })
    .catch((err) => {
      if (err.code === 'ERR_CANCELED') return          // ② 取消不算错误
      setError(...)
    })

  return () => controller.abort()                      // ③ cleanup 里取消
}, [keyword])
```

**为什么必须写在 cleanup 里**：React 的规则是"依赖变了 → 先跑上一次的 cleanup → 再跑新一次 effect"，
所以顺序天然正确：**先掐掉旧的，再发新的**。

### 三个细节（都会踩）

| 细节 | 说明 |
|---|---|
| `ERR_CANCELED` 不能提示用户 | 是你自己取消的，不是故障 |
| 别用 `.finally(() => setLoading(false))` | 被取消的那次也跑 finally → 把新请求的 loading 关掉 → 界面卡住 |
| 别用"标记变量"骗自己 | `let ignore = true` 也能让显示正确，但请求还在跑、流量还在烧 |

## 十二、FAQ

| 现象 | 原因 | 修 |
|---|---|---|
| 一直转圈不动 | 响应拦截器忘了 `Promise.reject`，错误被吞 | 补 `return Promise.reject(error)` |
| 所有请求都变成 undefined | 请求拦截器忘了 `return config` | 补 return |
| 页面白屏 + `Cannot read properties of undefined (reading 'map')` | 剥了 data 但按 AxiosResponse 用（或反过来） | 统一约定：要么全剥，要么全不剥 |
| 搜索时偶尔显示上一个词的结果 | **竞态** | 加 `AbortController` + cleanup 里 abort |
| 控制台一堆 `ERR_CANCELED` 红字 | 取消时没忽略 | `catch` 里先判断 `err.code` |
