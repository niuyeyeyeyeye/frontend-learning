# React 命名对照表（读名字就能猜出职责）

> 用途：看到一个陌生组件/hook/变量名，先拆结构，再翻词根。
> 以后每个 `dayN` 文件开头我也会放一份"本文件名字对照表"。
>
> ⚠️ 先说一句重要的：**代码里的名字必须用英文**（团队协作、搜索、第三方库全是英文）。
> 我们要做的是"看得懂"，不是"改成中文"。看懂了，写的时候就能想起该用哪个词。

---

## 一、⭐ 先学"结构"：名字的固定套路

这是最有用的部分 —— 英文词可以不认识，但**前缀/后缀**一看就知道它是什么。

| 形式 | 含义 | 项目里的例子 |
|---|---|---|
| `useXxx` | 一个 **hook**（能在里面调用其他 hook，只能在组件/hook 里调） | `useTheme` `useTodos` `useDebounce` |
| `onXxx` | **别人传给我的回调**（"当…发生时，请调我"） | `onClick` `onChange` `onSubmit` `onStep` |
| `handleXxx` | **我自己内部写的事件处理函数**（接住上面的 `onXxx`） | `handleSubmit` `handleDelete` |
| `isXxx` / `hasXxx` / `canXxx` | **布尔值**（是/否） | `isOpen` `hasError` `canSubmit` |
| `setXxx` | state 的**修改函数**（`useState` 自动给的） | `setTheme` `setText` `setPrice` |
| `toggleXxx` | **取反**（开↔关） | `toggleTheme` `useToggle` |
| `XxxList` | **数组** | `TodoList` `ResultList` |
| `XxxMap` / `XxxById` | **对象 / 映射表** | `userById` |
| `XxxProps` | 组件的 **props 类型** | `SearchInputProps` `QtyInputProps` |
| `XxxContextValue` | Context 里**装的东西**的类型 | `ThemeContextValue` `UserCtx` |
| `XxxProvider` | **往下发数据**的组件（发报机） | `ThemeProvider` `TodoProvider` |
| `xxxRef` | `useRef` 的变量 | `inputRef` `nextId` |
| `xxxId` | **唯一标识** | `todoId` `nextId` |
| `ALL_XXX` / `XXX_XXX` | **常量**（全大写，读代码的人一眼知道"不会变"） | `ALL_FRUITS` `INITIAL_TODOS` `THEME_BG` |
| `XxxDemo` / `XxxDemoPanel` | **演示用**组件（不是生产代码） | `PropDrillingDemo` `RerenderDemo` |
| `XxxLayout` / `XxxSection` / `XxxPanel` / `XxxCard` | **排版/包裹层**（自己不装数据，只摆放） | `TodoLayout` `MiddleLayer` `ProfileCard` |
| `xxxValue` | 一个"值"（尤其是传给 Provider 的那个对象） | `goodValue` `badValue` |
| `children` | **子元素**（标签中间夹的东西） | `<Provider>{children}</Provider>` |
| `initialXxx` / `defaultXxx` | **初始值 / 默认值** | `initialValue` `INITIAL_TODOS` |
| `nextXxx` / `prevXxx` | **下一个 / 上一个** | `next` `nextId` `usePrevious` |

### 一条铁律：**一个名字只能有一份含义**

同一个文件里，`TodoStats` 不能既是"统计数据的类型"又是"显示统计的组件" —— 读代码的人会疯。
（Day6 实战文件里我一开始就写了这个 bug，现在已改成 `TodoSummary` 类型 + `TodoStats` 组件。）

## 五、自测：只靠"结构"，猜这些名字是干什么的

（不许查，先猜，再往下翻）

1. `useDebouncedValue`
2. `onSearchChange`
3. `hasPermission`
4. `todoById`
5. `CartProvider`
6. `renderFooter`
7. `INITIAL_FORM_STATE`
8. `isSubmitting`
9. `useUserProfile`
10. `OrderItemList`

<details>
<summary>答案（先自己猜完再点）</summary>

1. `useDebouncedValue` — 一个 hook：**返回"防抖之后的某个值"**（`use` = hook，`debounced` = 已防抖，`Value` = 值）
2. `onSearchChange` — **父传下来的回调**：搜索框内容变化时触发（`on` = 回调）
3. `hasPermission` — **布尔**：有没有权限（`has` = 有）
4. `todoById` — **映射表/对象**：以 id 为键取待办（`ById` = 按 id）
5. `CartProvider` — **组件**：往下发购物车数据（`Provider` = 提供者）
6. `renderFooter` — **函数**：渲染页脚（`render` = 渲染，动词开头 = 干活的函数）
7. `INITIAL_FORM_STATE` — **常量**：表单的初始状态（全大写 = 不变）
8. `isSubmitting` — **布尔**：是否正在提交（`is` + 进行时）
9. `useUserProfile` — **hook**：拿用户资料（可能在内部发请求）
10. `OrderItemList` — **数组**（可能是组件或数据）：订单项列表（`List` = 列表）

</details>

## 六、我以后的做法（约定）

1. **每个 `dayN` 文件开头**：放一份"本文件名字对照表"（像上面第三节）
2. **关键声明处**：直接跟一句中文，例如
   ```tsx
   function useTodos(): TodoContextValue {   // 中文：用待办（从 Context 里取待办数据+操作）
   ```
3. **对话里**：第一次出现的名字，我会顺手给一句翻译，不再让你猜
4. **你自己写代码时**：先想"这是名词还是动词"——
   - 名词（`todoList` / `user` / `price`）→ 存数据
   - 动词开头（`handleSave` / `fetchUser` / `renderFooter`）→ 干活
   - `on` 开头 → 别人给你的回调　`use` 开头 → hook　`is/has/can` 开头 → 布尔
