## 核心循环（记住这个，所有页面都是它）

```
数据（数组）  →  render()  →  用户操作  →  改数据  →  再 render()
```

React 帮你做了 `render()` 那部分；原生 JS 要你自己写 `render()` 和"改 DOM"。

---

## Step 0：静态骨架（5 分钟）

写一个 HTML，只有三样东西：

```html
<input id="input" placeholder="输入待办">
<button id="add">添加</button>
<ul id="list"></ul>
```

**目标**：页面上有三个元素。点"添加"没反应 —— **正常**，因为还没写逻辑。

---

## Step 1：数据 + render 函数（10 分钟，最重要的一步）

```js
let todos = []        // ① 数据（唯一数据源）

function render() {   // ② 渲染函数：把数据"画"到页面上
  const list = document.querySelector('#list')
  list.innerHTML = ''                    // 先清空（否则会重复堆叠 —— 你踩过这个坑）
  todos.forEach((todo) => {
    const li = document.createElement('li')
    li.textContent = todo.text
    list.appendChild(li)
  })
}

render()  // 启动时渲染一次
```

**验证方法**：打开控制台，手动执行：

```js
todos.push({ id: 1, text: '手动测试', done: false })
render()
```

页面上应该出现"手动测试"。

> ⭐ **这一步是整个模式的核心**：以后所有操作都是"改 todos 然后调 render()"，**不要手动 appendChild 某一个元素**。

---

## Step 2：添加（10 分钟）

```js
document.querySelector('#add').addEventListener('click', () => {
  const input = document.querySelector('#input')
  const text = input.value.trim()
  if (!text) return                       // 空输入不添加

  todos.push({ id: nextId++, text, done: false })   // ① 改数据
  input.value = ''                                    // ② 清空输入框
  render()                                            // ③ 重新渲染
})
```

> ⚠️ **id 别用 `Date.now()`**（这是个真实的坑）：
> 我在写参考实现时用了 `Date.now()`，结果测试时"连续添加两条"抓到 id **重复**了 ——
> 因为两条是在同一毫秒内添加的。id 重复会导致"删一条删掉两条"。
>
> ✅ 正确做法：自己维护自增 id
> ```js
> let nextId = todos.reduce((max, t) => Math.max(max, t.id), 0) + 1   // 启动时恢复
> // 添加时：{ id: nextId++, ... }
> ```
> **这也是"为什么 React 里我用 nextId 而不是 Date.now()"** 的原因 —— 同一个道理。

**目标**：输入内容点"添加"，列表出现新项；输入框自动清空。

**对比 React**：React 里这就是 `setTodos([...todos, {...}])` —— 一步到位。原生要多写"清空输入框"和"手动 render"。

---

## Step 3：删除（10 分钟，考的是事件委托）

改 `render()`，给每个 li 加一个删除按钮：

```js
todos.forEach((todo) => {
  const li = document.createElement('li')
  li.textContent = todo.text

  const del = document.createElement('button')
  del.textContent = '删除'
  del.dataset.id = String(todo.id)     // 把 id 存在 DOM 上（Day5 学的 dataset 是 string）
  li.appendChild(del)

  list.appendChild(li)
})
```

然后**在父元素上**监听（事件委托 —— 因为按钮是动态创建的）：

```js
document.querySelector('#list').addEventListener('click', (e) => {
  if (e.target.tagName !== 'BUTTON') return
  const id = Number(e.target.dataset.id)
  todos = todos.filter((t) => t.id !== id)   // ① 改数据（造新数组）
  render()                                    // ② 重新渲染
})
```

**目标**：点删除能删掉对应那一条。

> ⚠️ 如果直接在循环里给每个按钮 `addEventListener`，每渲染一次就会**重复绑定一次** ——
> 这就是为什么用"事件委托"绑在父元素上（Day6 学过）。

---

## Step 4：切换完成状态（10 分钟）

改 `render()`，li 上加点击切换：

```js
li.className = todo.done ? 'done' : ''
li.addEventListener('click', (e) => {
  if (e.target.tagName === 'BUTTON') return     // 点删除按钮时不切换
  todos = todos.map((t) => (t.id === todo.id ? { ...t, done: !t.done } : t))
  render()
})
```

CSS 加一句：`.done { text-decoration: line-through; color: #999; }`

**目标**：点文字变灰划线，再点恢复。

> 注意：这里在循环里绑了 click（会出现"重复绑定"问题吗？）—— 因为 `li` 每次 render 都是**新的 DOM 节点**，
> 新的节点绑新事件，不会重复 ✅。但**父元素** `#list` 是不变的，所以父元素上的监听如果在 render 里绑定就会重复。

---

## Step 5：持久化（10 分钟，考 localStorage）

两处改动：

```js
// ① 启动时读取（没有就空数组）
let todos = JSON.parse(localStorage.getItem('todos') || '[]')

// ② 每次 render 后保存（或者每个操作后保存都行）
function save() {
  localStorage.setItem('todos', JSON.stringify(todos))
}
```

每个操作（添加/删除/切换）改完数据后调 `render()` + `save()`。

**目标**：刷新页面数据还在。

> 注意：你 Day6 踩过的坑 —— 读出来是 `null` 时不要直接 `JSON.parse(null)`（得到 null），
> 要用 `|| '[]'` 兜底。

1. **回车提交**：
```js
input.addEventListener('keydown', (e) => { if (e.key === 'Enter') addTodo() })
```
2. **空列表提示**：`if (todos.length === 0) { list.innerHTML = '<p>还没有待办</p>'; return }`
3. **统计**：`未完成 N 条`（`todos.filter(t => !t.done).length`）

## 写完之后，问自己三个问题（这才是有价值的部分）

1. **React 到底替你做了什么？**
   - `render()` 不用你写 → React 帮你把"数据"变成"DOM"
   - `appendChild` / `innerHTML` / `dataset` / 事件绑定 → React 打包成了"声明式渲染"
   - **但"数据变了要重新渲染"这个循环，你一定得懂** —— 不然你会以为"改数据后页面会自动变"是魔法
2. **为什么 React 里不写 render()？**
   - 因为 React 用 diff 找出"哪里变了"，只改必要的 DOM（性能更好）
   - 而你手动 `innerHTML = ''` 是**整个列表重建**（性能差 + 输入框状态会丢 —— 这就是 Day3 的 key bug）
3. **面试如果让你手写原生 JS 待办，你能写出来吗？**
   - 现在你可以了 —— 而且能讲清"为什么 React 要发明这一套"
