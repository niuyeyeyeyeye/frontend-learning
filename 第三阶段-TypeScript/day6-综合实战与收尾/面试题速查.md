## 一、基础概念（几乎必问）

**1. TypeScript 和 JavaScript 是什么关系？**
> TS 是 JS 的**超集**：JS 的语法它都支持，额外加了静态类型。
> TS 要**编译成 JS** 才能运行（浏览器/Node 只认 JS）。
> 它最大的价值：**在写代码时就发现类型错误**，而不是等运行时崩。

**2. 类型信息在运行时还有吗？**
> **没有**。TS 的类型是"编译时"的，编译后全部被擦除（type erasure）。
> 推论：**不能用 TS 校验后端返回的数据**——`as T` 不会检查运行时结构，必须靠类型守卫或 zod 之类的库。

**3. `interface` 和 `type` 的区别？**
> - 都能描述对象形状
> - **interface**：能"声明合并"（同名自动合并，适合扩展第三方类型）、用 `extends` 继承
> - **type**：能定义**联合类型**、给基本类型起别名、用 `&` 交叉
> - 实践：**描述对象用 interface，联合/别名/组合用 type**

**4. `any` / `unknown` / `never` 的区别？**
> - **any**：关掉类型检查（能用任何属性、能赋给任何类型）→ **等于 TS 白装**
> - **unknown**：未知但安全——用之前必须收窄（`typeof` / 判断）
> - **never**：永远不会出现的值。两个用途：① 抛错函数不返回 ② **穷举检查**（switch 里 `default: assertNever(x)`，漏了分支会立刻报错）

**5. 什么是类型收窄（narrowing）？怎么收窄？**
> 联合类型必须先判断才能安全使用某一侧，判断后类型"变小"就叫收窄。
> 手段：`typeof` / `===` 字面量比较 / `in` / `instanceof` / `Array.isArray` / 自定义守卫 `v is T`

**6. `??` 和 `||` 的区别？（高频）**
> - `||` 处理**所有假值**：`0`、`''`、`false`、`null`、`undefined`、`NaN`
> - `??` **只处理 `null` / `undefined`**
> - 给"可能是 0 或空字符串"的数据设默认值，必须用 `??`

**7. `readonly` 和 `const` 的区别？**
> `const` 是变量的绑定不可变；`readonly` 是**属性**不可变（对象属性、数组元素）。
> `Readonly<T>` 可以把一个类型的所有属性变只读。

## 二、进阶（拉开差距的地方）

**8. 泛型是什么？什么时候该用？**
> 泛型是**类型的参数**，让函数/接口处理多种类型的同时保留类型信息。
> **判断标准：类型参数至少在两个地方出现**（比如参数和返回值），用来建立"进和出"的关联。
> 反例：`function log<T>(msg: T): void` —— T 只出现一次，等价于 `unknown`，不该用泛型。

**9. 泛型约束 `extends` 用过吗？**
> `<T extends { length: number }>` 限制 T 必须有 length；
> **最常用的是 `<K extends keyof T>`**：保证 K 一定是 T 的属性名，配合 `T[K]`（索引访问类型）返回对应类型。

**10. 工具类型用过哪些？说说真实场景。**
> - `Omit<T, 'id'>`：新增时不需要 id
> - `Pick<T, 'id' | 'name'>`：列表只显示部分字段
> - `Partial<T>`：更新接口只传要改的字段
> - `Record<K, V>`：字典（如 `Record<string, User>`）
> - `ReturnType<typeof fn>`：拿到函数返回类型（定时器 `ReturnType<typeof setTimeout>` 两边通用）
> - `Required` / `Readonly` / `Parameters`：知道就行

**11. `as` 和 `!` 有什么风险？**
> 两者都是"**你向 TS 保证**"，**TS 不做任何检查**。保证错了 → 编译通过、运行时崩。
> 能用判断/类型守卫/`??` 解决的，就别用它们。
> （典型：`document.querySelector('#x')!` 元素不存在时运行时 TypeError）

**12. 怎么给"key 和 value 的对应关系"做类型检查？**
> 用一个"映射表"接口 + `keyof` + 索引访问：
> ```ts
> interface StorageSchema { todos: Todo[]; theme: string }
> function set<K extends keyof StorageSchema>(key: K, value: StorageSchema[K]): void
> ```
> 只写 `set<T>(key: string, value: T)` 是**拦不住**"给 todos 存字符串"的。

**13. `strict: true` 都开了什么？最重要的是哪个？**
> 一整套严格检查，最重要的是 **`strictNullChecks`**：`null`/`undefined` 不再能随便赋给别的类型，
> 所以"可能是 null"的值用之前必须判断。这是 TS 帮你挡 bug 最强的一项。

**14. 第三方库没有类型怎么办？**
> ① 先看有没有 `@types/库名`（`npm i -D @types/xxx`）
> ② 没有就自己写声明文件 `xxx.d.ts`：
> ```ts
> declare module 'some-lib' {
>   export function doSomething(input: string): number
> }
> ```
> ③ 临时应急可以用 `declare module 'some-lib'` 给个 `any`（但别长期这样）

## 三、加分项（了解即可，答出来很亮眼）

**15. `satisfies` 是什么？（TS 4.9+）**
> 既检查类型、又保留**字面量推断**。适合配置对象：
> ```ts
> const config = { theme: 'dark', size: 'large' } satisfies Record<string, string>
> // config.theme 的类型仍然是 'dark'（字面量），而不是 string
> ```

**16. 为什么现在不推荐用 `enum`？**
> 现代实践倾向用 **字面量联合 + `as const`** 代替：类型更精确、体积更小（enum 会生成运行时代码）、和 JS 生态更兼容。

**17. TS 类型的"擦除"对运行时校验意味着什么？**
> 意味着所有类型校验只存在于编译期。**接口数据必须做运行时校验**（手写类型守卫或用 zod/valibot 这类库）。
> —— 这一条能答出来，面试官会觉得你真用过 TS，而不只是"会写类型标注"。

**18. 类型体操了解多少？**
> 诚实答：**工作中极少手写**，会读、会用内置工具类型就够了。
> 复杂类型（条件类型、映射类型递归、infer）遇到再查。
> （**不要硬吹**，面试官会追问到你说不出来为止）

## 四、怎么答 TS 面试题（策略）

1. **先给"是什么"，再给"为什么/什么时候用"**——只背定义会显得像背题
2. **举一个你自己写过的例子**：你有现成的素材（typedStorage、$ 辅助函数、debounce 泛型、TodoStore）
3. **不会的直说 + 说出相关的那部分**：比如"类型体操我很少手写，但我知道 `infer` 是用来在条件类型里提取类型的"
4. **别硬吹**：写"精通 TS"会被一路深挖到底
