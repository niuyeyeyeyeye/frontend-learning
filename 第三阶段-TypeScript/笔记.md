## 二、语法速记

```ts
// 变量
const name: string = '小明'
const age: number = 18
const tags: string[] = ['a', 'b']              // 数组
const point: [number, number] = [3, 4]         // 元组（少用）
const user: { name: string; age: number } = { name: '小红', age: 20 }   // 对象

// 函数：参数必须写类型，返回值可省略（能推断）
function add(a: number, b: number): number { return a + b }
function greet(name: string, title?: string): string { ... }   // ? = 可选参数
function repeat(text: string, times: number = 2): string { ... }  // 默认值
function log(msg: string): void { ... }        // 没有返回值 → void

// 联合类型 + 字面量类型
type TodoStatus = 'todo' | 'doing' | 'done'    // 只能填这三个
function printId(id: number | string) { ... }  // 可能是两种之一
```

## 三、必须记住的三条

1. **能推断出来就不用写**：`const city = '武汉'` 已经是 string。**但函数参数必须写**（TS 推不出来）
2. **别用 `any`**：`any` = 关掉类型检查 = TS 白装。不确定用 `unknown` + `typeof` 判断
3. **strict 模式下 null 必须先判断**：`text === null` 之后才能用 `text.length`

> 学习技巧：**把鼠标悬停在变量上**，编辑器会显示推断出的类型 —— 这是学 TS 最快的方法。

# Day2：对象建模（interface / type）

> 日期：2026-10-09
> 文件：`day2-对象建模\讲解.ts`（讲解）、`day2-对象建模\练习.ts`（8 个错误待修）、`day2-对象建模\报错示例.ts`

## 一、核心语法速记

```ts
interface User {
  readonly id: number        // 只读：创建后不能改
  name: string
  summary?: string           // 可选：可以不存在
  tags: string[]             // 数组
  address: Address           // 嵌套对象
  friends: User[]            // 对象数组
  add(a: number): number     // 方法
  [key: string]: number      // 索引签名（键名不确定）
}

type ID = string | number              // 别名 + 联合
type Status = 'todo' | 'doing'         // 字面量联合
type A = B & C                         // 交叉（把两个类型合并）
interface Product extends BaseEntity { name: string }   // 接口继承
const scores: Record<string, number> = { 语文: 90 }      // 字典
```

## 二、interface vs type（面试常问）

| 能力 | interface | type |
|---|---|---|
| 描述对象形状 | ✅ | ✅ |
| 联合类型 `'a' \| 'b'` | ❌ | ✅ |
| 给基本类型起别名 | ❌ | ✅ |
| 组合两个类型 | `extends` | `&` 交叉 |
| 声明合并（同名自动合并） | ✅ | ❌ 重复定义直接报错 |

**实践建议**：描述对象/数据结构用 `interface`；联合、别名、组合用 `type`。
**别纠结**——团队用哪个就跟着用哪个。

## 三、Day2 新增报错码

| 错误码 | 含义 |
|---|---|
| **TS2741** | 缺少必需属性（Property 'x' is missing...） |
| **TS2353 / TS2561** | 对象字面量多写了属性 / 属性名拼错（TS2561 会附上 "Did you mean to write 'title'?" 的建议） |
| **TS2540** | 不能给只读属性赋值 |
| **TS18048** | 'x' is possibly 'undefined'（可选属性没判断就用） |
| **TS2717** | 接口里同名属性的类型冲突 |

## 四、实用经验（真实项目里踩过的）

- **邮编 / 手机号 / 身份证号 / 订单号都用 `string`**，别用 `number`——数字会丢前导零（`'043000'` 变成 `43000`）
- `readonly` 表示"只读"：要改值就在创建对象时定好；真需要可变就别加它
- 可选属性用之前必须判断（Day3 学更简洁的 `?.` 和 `??`）
- 报错信息里出现 **"Did you mean to write ..."** 时，TS 已经告诉你答案了，直接看

# Day3：类型收窄与安全访问

> 日期：2026-10-09
> 文件：`day3-类型收窄\讲解.ts`、`练习.ts`（10 个错误待修）、`报错示例.ts`

## 一、什么是"收窄"

变量是**联合类型**（可能是 A 也可能是 B）时，TS 要求你**先判断**，才允许用某一侧的方法。
判断之后类型"变小"了 —— 这个过程叫**收窄（narrowing）**。

| 判断方式 | 用在哪 | 例子 |
|---|---|---|
| `typeof x === 'string'` | 基本类型 | `function f(v: string \| number)` |
| `x === 'todo'` | 字面量联合 | `type Status = 'todo' \| 'doing'` |
| `if (r.ok)` / `r.type === 'cat'` | **可辨识联合**（最常用） | 接口返回值 `{ ok: true, data }` / `{ ok: false, error }` |
| `'meow' in pet` | 判断有没有某个属性 | 猫和狗的结构不同时 |
| `x instanceof ApiError` | 类实例 | 处理 `catch (e: unknown)` |
| `Array.isArray(x)` | 数组 | `string \| string[]` |
| `isUser(v)`（自定义守卫） | 接口数据 | 见下面第五节 |

## 二、⭐ `??` 和 `||` 的区别（面试常问）

```ts
const zero: number | null = 0
zero || 100   // 100  ❌ 0 是假值
zero ?? 100   // 0    ✅ 只有 null/undefined 才用默认值

'' || '默认'   // '默认' ❌
'' ?? '默认'   // ''     ✅
```

- `||` 处理**所有假值**：`0`、`''`、`false`、`null`、`undefined`、`NaN`
- `??` **只处理 `null` / `undefined`**
- 给"可能是 0 / 空字符串"的数据设默认值 → **必须用 `??`**

## 三、⚠️ 真值判断的坑

```ts
if (count) { ... }          // ❌ count 为 0 时会被当成"假"，逻辑就错了
if (count !== null) { ... } // ✅ 该明确判断就明确判断
```

**真值判断会把这些当成"假"**：`0`、`''`、`false`、`null`、`undefined`、`NaN`。
只有当你**确实想**把这些都排除时才用 `if (x)`。

## 四、`?.` / `as` / `!` 三件套

```ts
obj?.a?.b          // 安全取属性
arr?.[0]           // 安全取下标
props.onClick?.()  // 安全调用函数（React 里天天见）
```

| 写法 | 含义 | 危险程度 |
|---|---|---|
| `?.` | 安全的"可能是空"访问 | ✅ 推荐 |
| `as T` | "我保证它是 T" —— **不做任何检查** | ⚠️ 慎用 |
| `x!` | "我保证不是 null/undefined" | ⚠️⚠️ 更危险 |

**判断标准**：用 `as` / `!` 之前先问自己——**"如果它其实不是这个类型，运行时会怎样？"**
能用 `if` 判断或类型守卫解决的，就别用它们。

## 五、处理接口数据的正解：类型守卫

```ts
function isUser(v: unknown): v is User {
  return typeof v === 'object' && v !== null && 'id' in v && 'name' in v
}

function printUser(data: unknown) {
  if (isUser(data)) {
    console.log(data.name)      // ← 这里 data 被收窄成 User
  }
}
```

**返回值里的 `v is User` 是关键** —— 它让调用方能收窄。这是处理"后端数据不可信"的标准做法。

# Day4：泛型与工具类型

> 日期：2026-10-10
> 文件：`day4-泛型与工具类型\讲解.ts`、`练习.ts`（9 个错误待修）、`报错示例.ts`

## 一、泛型是什么

**泛型 = 类型的参数。** 让函数/接口既能处理各种类型，又不丢类型信息。

```ts
function first<T>(arr: T[]): T | undefined { return arr[0] }

const n = first([1, 2, 3])    // number | undefined
const s = first(['a'])        // string | undefined
```

对比用 `any` 的写法：`function firstAny(arr: any[]): any` —— 能跑，但类型信息全丢，后续写什么都没保护。

## 二、泛型约束 `extends`

```ts
// T 必须"有 length 属性"
function longest<T extends { length: number }>(a: T, b: T): T { ... }

// ⭐ 最常用的约束：K 必须是 T 的属性名
function getProp<T, K extends keyof T>(obj: T, key: K): T[K] { return obj[key] }
getProp(user, 'name')     // string
getProp(user, 'nope')     // ❌ 报错
```

## 三、工具类型（记 4 个就够）

| 工具类型 | 作用 | 真实场景 |
|---|---|---|
| `Omit<T, 'a' \| 'b'>` | 去掉几个属性 | 新增用户时不需要 `id`/`createdAt` |
| `Pick<T, 'a' \| 'b'>` | 只挑几个属性 | 列表项只显示部分字段 |
| `Partial<T>` | 全部变成可选 | 更新接口（只传要改的字段） |
| `Record<K, V>` | 字典 | `Record<string, User>` |

（还有 `Required` / `Readonly` / `ReturnType` / `Parameters`，用到再查，别背）

## 四、⭐ 一个实测发现的坑：`Omit` 传错键名**不报错**

```ts
type A = Omit<User, 'nope'>   // ⚠️ 编译通过！等于把 User 原样抄了一遍
type B = Pick<User, 'nope'>   // ✅ 报 TS2344：'nope' 不满足 keyof User
```

原因：`Omit<T, K extends keyof any>` 的约束是"**任意字符串**"，而 `Pick<T, K extends keyof T>` 才是"**T 的属性名**"。

**结论：想校验键名拼写就用 `Pick`；用 `Omit` 时自己核对属性名。** 这种"编译通过但写错了"的坑比报错更危险。

## 五、什么时候【不要】用泛型（比语法重要）

- ❌ `function log<T>(msg: T): void` —— T 只出现一次，没建立任何关联，等价于 `msg: unknown`
- ✅ **判断标准：类型参数至少在两个地方出现**（如参数和返回值），用来关联"进和出"
- ✅ 另一个信号：多个调用方共用同一份逻辑、但类型不同（数组取值、请求封装、状态容器）

# Day5：用 TS 改写旧练习（DOM / 异步 / 防抖节流）

> 日期：2026-10-13
> 文件：`day5-改写旧练习\讲解.ts`、`练习.ts`（11 行报错待修）、`报错示例.ts`
> ⚠️ 这个文件夹是 DOM 代码，**不要在 node 里跑**，在 VS Code 里看类型提示最好

## 一、DOM 的三个坑（TS 里最容易踩）

1. `querySelector` 找不到元素时返回 **null**
2. `querySelector` 返回的是 **Element**（很宽泛），没有 `.value` / `.placeholder`
3. 事件回调里的 **`e.target` 是 EventTarget**，没有 `.dataset` / `.value`

## 二、⭐ 最佳实践：`$` 辅助函数（真实项目到处都有）

```ts
function $<T extends HTMLElement>(selector: string): T {
  const el = document.querySelector<T>(selector)
  if (el === null) throw new Error('找不到元素：' + selector)
  return el
}

const input = $<HTMLInputElement>('#todoInput')
input.value = 'hello'        // ✅ 有类型、不用断言、不会 null
```

好处：① 类型自动正确 ② 不用到处写 `if (=== null)` ③ 找不到时**立刻**报明确错误，
而不是让 null 传到后面变成更难查的 bug。

## 三、事件类型速查

| 事件 | 类型 |
|---|---|
| click / dblclick / mousemove | `MouseEvent` |
| keydown / keyup | `KeyboardEvent` |
| input / change | `Event`（要拿 value 就断言 target） |
| submit | `SubmitEvent` |
| focus / blur | `FocusEvent` |

**大部分能自动推断**，只有需要具体属性时才手写标注。

## 四、`e.target` 的三种处理

```ts
const t = e.target as HTMLElement                    // 断言（短，但"你保证"）
if (e.target instanceof HTMLElement) { ... }         // 安全（推荐，Day3 学的收窄）
const li = (e.target as HTMLElement).closest('li')   // 事件委托找祖先，最常用
```

## 五、⚠️ `dataset` 的类型是 `string | undefined`

`data-index="3"` 取出来是 **`'3'`（字符串）**，不是 `3`。用之前要 `Number(...)`。
—— **HTML 属性都是字符串**，这是很多人栽的地方。

## 六、定时器的类型

```ts
let timer: ReturnType<typeof setTimeout> | null = null
```

- 浏览器里 `setTimeout` 返回 `number`，Node 里是 `NodeJS.Timeout` → **`ReturnType` 两边通用**
- ⭐ **实测发现的规则**（我特意验证过）：
  `let x = null` 在**同一个函数内**赋值读取 **不报错**（TS 叫 "evolving any"）；
  一旦**跨函数**读写，就报 **TS7034 / TS7005**（implicitly has type 'any'）
- 更重要的是：不标注的那段时间它就是个 `any`，**等于没有类型保护** → 定时器变量一律主动标注

## 七、localStorage 泛型封装（Day6 的 JS 版升级）

```ts
const storage = {
  get<T>(key: string, defaultValue: T): T { ... },
  set<T>(key: string, value: T): void { ... },
}
const todos = storage.get<Todo[]>('todos', [])   // T 自动推断成 Todo[]
```

⚠️ 但记住：`JSON.parse(raw) as T` **不校验运行时数据**。后端结构不对时它照样通过，
要到用的时候才崩。严谨场景要配类型守卫（Day3 的 `is T`）或 zod 这类校验库。

### ⭐ 重要局限：`set<T>(key: string, value: T)` 拦不住"存错类型"

我原本在讲解里写"`storage.set('todos', '字符串')` 会被 TS 拦下来"—— **这是错的，实测不报错。**

```ts
storage.set('todos', '字符串')   // ⚠️ 合法！T 被推断成 string，key 只是个普通 string
```

**原因**：泛型只能表达"参数之间的关系"。`key: string` 和 `value: T` 之间**没有任何关系**，
所以 TS 无从判断"todos 这个 key 应该配 Todo[]"。

**正确做法：把「key → 类型」的对应关系写成类型定义**（用 Day4 的 `keyof` + 索引访问类型）：

```ts
interface StorageSchema {
  todos: Todo[]
  theme: string
}
const typedStorage = {
  get<K extends keyof StorageSchema>(key: K, defaultValue: StorageSchema[K]): StorageSchema[K] { ... },
  set<K extends keyof StorageSchema>(key: K, value: StorageSchema[K]): void { ... },
}

typedStorage.set('theme', 'dark')      // ✅
typedStorage.set('todos', '字符串')    // ❌ TS2345（实测验证过）
typedStorage.set('name', 'x')          // ❌ 'name' 不在 StorageSchema 里
```

这就是真实项目里"类型安全的 storage"的写法。

## 八、防抖 / 节流的"专业类型"（用泛型参数元组）

```ts
function debounce<A extends unknown[]>(
  fn: (...args: A) => void,
  delay = 300,
): (...args: A) => void
```

好处：debounce 出来的函数，**参数类型和原函数完全一致**——少传、传错都会报错。
（这就是泛型真正的价值：把"进来的类型"和"出去的类型"关联起来，Day4 学的判断标准。）

**三个值得记住的设计点**：

1. **依赖注入**：`constructor(initial: Todo[] = [], storage: StorageLike = new MemoryStorage())`
   —— 存储从外面传进来，所以**同一个存储可以被多个 store 共用**，代码也能在 Node 里跑（不依赖 localStorage）
2. **不可变更新**：`this.todos = [...this.todos, todo]` / `filter` / `map`

3. **`never` 做穷举检查**：
   ```ts

   ```
   以后给 `Filter` 加新值，这里会**立刻报错**提醒你补逻辑

## 二、`never` 的两种用途（面试常问）

```ts
// ① 抛错的函数永远不返回
function fail(msg: string): never { throw new Error(msg) }

// ② 穷举检查：确保所有分支都处理了
function assertNever(value: never): never {
  throw new Error('有未处理的情况：' + JSON.stringify(value))
}
switch (filter) {
  case 'all': ...
  case 'active': ...
  case 'done': ...
  default: return assertNever(filter)     // 漏了分支就报错
}
```
