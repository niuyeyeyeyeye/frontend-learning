## 知识点速记

### 一、模块化
- `type="module"` 的 5 个特性：严格模式 / 独立作用域 / **顶层 this 是 undefined** / 自动 defer / 支持 import-export
- 导出：`export const x`、`export function f(){}`、`export { a, b }`、`export default fn`
- 导入：`import { a } from './x.js'`、`import f from './x.js'`、`import * as utils from './x.js'`、`import { a as b }`
- 规则：一个模块只有 1 个 default；路径要带 `.js`；import 必须在顶层；同一模块只执行一次（单例）；条件加载用 `await import()`

### 二、闭包
- 定义：函数 + 它能记住的外部变量。外层函数执行完，变量因被引用而不销毁
- 用途：计数器、私有变量（模拟 private）、缓存 memoize、防抖 debounce、模块模式
- 经典坑：`for (var i...)` + 异步回调 → 输出 3 3 3；换 `let` 得 0 1 2（var 函数作用域 / let 块级作用域）
- 代价：变量常驻内存，不用了记得置 `null`

### 三、this 指向（判断顺序）
1. **箭头函数** → 没有自己的 this，取定义时外层的 this
2. **`new` 调用** → 新建的那个对象
3. **call / apply / bind** → 指定的对象（bind 优先级仅次于 new）
4. **`obj.fn()`** → `obj`（只看紧挨着点的那个对象）
5. **其他（直接调用）** → 严格模式/模块里是 `undefined`，非严格是 `window`

- 三个高频坑：
  - `const fn = obj.method; fn()` → this 丢失
  - `setTimeout(obj.method, 100)` → this 丢失，用 `() => obj.method()` 修
  - 对象方法写成箭头函数 → 拿不到对象自身的属性
- `call`（逐个传参）/ `apply`（数组传参）/ `bind`（返回新函数，不立即执行）

## 面试高频（背下来能直接答）

- 闭包是什么？有什么缺点？→ 变量常驻内存，可能内存泄漏
- var / let / const 的区别？→ 作用域、变量提升、重复声明、常量
- 普通函数和箭头函数的区别？→ this、arguments、能不能 new、有没有 prototype
- ES Module 和 CommonJS 的区别？→ 编译时静态 / 运行时动态；值引用 vs 值拷贝
