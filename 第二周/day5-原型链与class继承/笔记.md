## 一、原型链（核心图，背下来）

```
实例 p  →  Person.prototype  →  Object.prototype  →  null
         (放方法 sayHi)        (放 toString 等)
```

- 访问属性时：**先找自己 → 再顺原型链往上找 → 到 null 返回 undefined**
- `p.__proto__` / `Object.getPrototypeOf(p)` → 对象自己的原型
- `Person.prototype` → 函数身上的普通属性，是"将来实例的原型"（**两个东西别搞混**）
- `Person.prototype.constructor === Person`
- 函数也是对象：`Object.getPrototypeOf(Person) === Function.prototype`
- 方法写在 prototype 上 → 所有实例共用一份，省内存
- `p.hasOwnProperty('name')` 只看自己；`'sayHi' in p` 会往原型链上找

### new 做了什么（4 步）
1. 创建空对象 `{}`
2. 空对象的原型指向 `Ctor.prototype`
3. 构造函数里的 `this` 指向空对象并执行
4. 构造函数没返回对象 → 返回这个空对象

### instanceof 原理
顺着 `obj` 的原型链往上找，看有没有等于 `Ctor.prototype` 的一环

## 二、class 语法

```js
class User {
  static count = 0        // 静态属性（挂在类上）
  #password               // 私有字段（外部访问直接报错）
  constructor(name) { this.name = name }
  method() {}             // 实例方法 → 实际在 User.prototype 上
  get info() {}           // getter
  set info(v) {}          // setter
  static create() {}      // 静态方法
}
```

- class = 构造函数 + prototype 的**语法糖**，底层还是原型链
- 两个"脾气"：**不提升（TDZ，必须先定义后用）**、**内部自动严格模式**
- `typeof User === 'function'`
- 实例方法在原型上：`u1.hasOwnProperty('method')` → false，但能调用
- `#私有字段` vs `_下划线`：# 是语法级私有，_ 只是约定

## 三、继承

```js
class Dog extends Animal {
  constructor(name, breed) {
    super(name)      // 必须在使用 this 之前调用
    this.breed = breed
  }
  speak() { return super.speak() + '：汪汪！' }   // 扩展而不是覆盖
}
```

- 底层结构：`Dog.prototype.__proto__ === Animal.prototype`
- 完整链：`dog → Dog.prototype → Animal.prototype → Object.prototype → null`
- 子类不写 constructor → 自动继承父类构造函数
- 静态成员也继承，且 `static create() { return new this() }` 里的 `this` 是**调用它的子类**
- 三层继承 + 同一个方法名不同表现 = **多态**
- 子类 constructor 里 `super()` 之前不能碰 `this`（报错 Must call super constructor...）

## 四、面试高频问答（能直接背）

1. **原型链是什么？** 对象访问属性时逐级向上查找的链，终点是 null；实现继承和属性共享的机制
2. **instanceof 原理？** 沿原型链查找是否出现 `Ctor.prototype`
3. **class 和构造函数的区别？** 语法糖；差异在：不提升、自动严格模式、必须 new 调用、方法不可枚举、有私有字段
4. **继承的几种实现方式？** 原型链继承、构造函数继承、组合继承、寄生组合继承（最优）、ES6 class extends
5. **方法为什么放 prototype 上？** 所有实例共享一份，省内存
6. **为什么推荐组合而不是继承？** 继承层级深了难维护；Vue 3 组合式 API 就是组合思路
