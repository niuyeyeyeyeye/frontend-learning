第 0 步：先补 3 个前置知识

看不懂防抖的答案，八成不是防抖难，而是卡在这 3 个小东西上。先把它们弄明白。

前置 1：函数可以"返回一个函数"

function outer() {
  const msg = '我是外面的变量'
  return function inner() {   // 返回一个函数
    console.log(msg)          // inner 还记得外面的 msg
  }
}

const f = outer()   // 执行 outer()，拿到的是 inner
f()                 // 打印：我是外面的变量
f()                 // 再打印一次：我是外面的变量
关键：outer() 早就执行完了，但 msg 没有消失，因为 inner 一直用着它。
这就是闭包——防抖能"记住上一次的定时器"，靠的就是这个。

前置 2：...args（剩余参数）

function sum(...args) {        // args 是一个数组，把传来的参数全收进去
  return args.reduce((a, b) => a + b, 0)
}

sum(1, 2, 3)   // 6
sum()          // 0
为什么防抖里要用它：防抖返回的那个函数，不知道外面会传几个参数进来， 所以先用 ...args 全部收下，等真执行时再原样交出去。

前置 3：fn.apply(this, args)

function hi(name) { console.log('你好 ' + name) }

hi.apply(null, ['小明'])   // 你好 小明
// apply 的两个参数：① 把 this 给谁  ② 参数数组（会被自动拆开）
说白了：fn.apply(this, args) = "用这里的 this，带着这些参数，去调用 fn"。
它的用处就是把外面传进来的东西，原封不动转交给真正的函数。

第 1 步：先看"最朴素"的写法（有问题的版本）

// 搜索框，每打一个字就搜索
input.addEventListener('input', () => {
  search(input.value)
})

// 打 "react" 5 个字母 → 触发 5 次搜索
// 问题是：请求太频繁，且返回顺序可能乱

我们的目标一句话：让它在用户"停下来"之后才执行，只执行最后一次。

第 2 步：用定时器手动实现（不封装，先看懂效果）

let timer = null                  // 准备一个变量，用来装定时器

input.addEventListener('input', () => {
  clearTimeout(timer)             // ① 把上一次还没执行的定时器取消掉
  timer = setTimeout(() => {      // ② 重新起一个：300ms 后执行
    search(input.value)
  }, 300)
})
跑一遍就明白了：你打字期间每敲一个字都会"取消上一个、重新计时"， 所以只有最后停下 300ms 后，那个定时器才有机会执行 → 总共只搜 1 次。
但这段代码有两个毛病：① timer 是"全局变量"，别人也能改它； ② 这段逻辑没法复用，第二个搜索框就要再抄一遍。
→ 第 3 步就是把这段逻辑"打包"成一个函数。

第 3 步：打包成 debounce（先看简化版！）

function debounce(fn, delay) {      // fn 是要执行的函数，delay 是等待时间
  let timer = null                  // ← 原来在全局，现在"藏"进函数里（闭包）
  return function () {              // ← 返回一个函数，外面用的就是它
    clearTimeout(timer)             // ① 取消上一次
    timer = setTimeout(fn, delay)   // ② 重新计时，到点执行 fn
  }
}

// 用法
const searchDebounced = debounce(search, 300)
input.addEventListener('input', () => {
  searchDebounced(input.value)      // 注意：调用的是 debounce 返回的那个函数
})
对照上面的第 2 步，其实一模一样，只是：
第 2 步（手动写）第 3 步（封装后）
let timer = null 写在全局写在 debounce 函数里 → 变成私有的，且被闭包记住
clearTimeout(timer)一样
setTimeout(() => search(...), 300)setTimeout(fn, delay)（换成参数，方便复用）
写死在事件监听里return function () {} 交出去，谁需要谁调用

运行一下，亲眼看到"只执行 1 次"

let count = 0
const say = () => {
  count++
  console.log('✅ 真正执行了，第 ' + count + ' 次')
}
const debouncedSay = debounce(say, 500)

// 模拟 1 秒内疯狂触发 10 次
for (let i = 0; i < 10; i++) debouncedSay()
console.log('触发了 10 次，等一下看真正执行几次 ↓')

预期：控制台先打印一行提示，0.5 秒后只打印 1 次「真正执行了，第 1 次」。

升级版：加上 ...args 和 apply

简化版有个缺陷：它不能把参数传进去（search(input.value) 里的关键词丢了）。所以真实版要加两个零件：

function debounce(fn, delay) {
  let timer = null
  return function (...args) {                              // ← 零件1：把参数收进来
    clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), delay)  // ← 零件2：原样转交给 fn
  }
}
// fn.apply(this, args) = 用当前的 this，带着这些参数，去调用 fn
先看懂简化版，再看升级版。升级版只是多了"把参数和 this 传进去"这件事， 骨架（clearTimeout + setTimeout）完全没变。

第 4 步：动手实验（比看十遍有用）

在控制台或文件里试，每做一步都记一句"我看到了什么"：

  1. 删行法：把 clearTimeout(timer) 注释掉 → 再触发 10 次 → 变成执行 10 次（防抖失效，退化成普通延时）
  2. 改数字：把 300 改成 3000 → 明显感到"要等很久才执行"； 改成 0 → 几乎立刻执行
  3. 看参数：在 return function (...args) 里加 console.log('收到的参数：', args) → 确认参数真的进来了
  4. 制造 bug：把 fn.apply(this, args) 改成 fn() → 参数和 this 都丢了（这就是 Day4 学的 this 丢失）
  5. 体会复用：用同一个 debounce 再包一个函数（比如 debounce(() => console.log('滚动结束'), 200)）→ 两个互不干扰， 因为各自的 timer 是独立的闭包变量

第 5 步：节流 throttle 也是同样套路（3 步）

目标：不管触发多快，每 500ms 最多执行 1 次。

// 第 1 步：思路 —— 记住"上次执行的时间"，跟现在比一比
// 第 2 步：手动版
let lastTime = 0
button.addEventListener('click', () => {
  const now = Date.now()                 // 现在的时间戳（毫秒）
  if (now - lastTime >= 500) {           // 距离上次执行够 500ms 了吗？
    lastTime = now                       // 记下这次的时间
    doSomething()                        // 执行
  }
})

// 第 3 步：打包（同样的闭包套路，只是变量从 timer 换成了 lastTime）
function throttle(fn, interval) {
  let lastTime = 0                       // 被闭包记住
  return function (...args) {
    const now = Date.now()
    if (now - lastTime >= interval) {
      lastTime = now
      fn.apply(this, args)
    }
  }
}
一句话分清：防抖是"你停下来我才动"（只认最后一次）； 节流是"我按自己的节奏动，你触发再快也没用"（固定频率）。
