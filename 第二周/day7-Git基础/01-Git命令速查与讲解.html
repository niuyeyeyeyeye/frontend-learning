Day7-1：Git 命令速查与讲解

做作业时把这一页开着，边看边敲。**命令一定要手打，不要复制粘贴**（手打才记得住）。

0. 先理解四个"区域"（理解了这个，Git 就不神秘了）

工作区 暂存区 本地仓库 远程仓库 (你正在编辑的文件) --add--> (准备提交的清单) --commit--> (.git 里的历史) --push--> (GitHub) <-- git restore（丢弃修改） <-- git restore --staged（取消暂存） <-- git pull / git fetch

一句话：**改文件 → add 挑出要提交的 → commit 拍张快照 → push 传到 GitHub**。

为什么要"暂存区"这么麻烦？因为它让你能**选择性地提交**：改了 5 个文件，只提交其中 2 个相关的，提交历史才清晰。

1. 一次性配置（今天第一件事）

# ① 设置身份（必须！否则提交不属于你）
git config --global user.name "你的GitHub用户名"
git config --global user.email "你的GitHub邮箱"

# ② 新仓库默认分支叫 main（而不是 master）
git config --global init.defaultBranch main

# ③ 让中文文件名正常显示（不然 git status 里是一堆 \344\275\240 乱码）
git config --global core.quotepath false

# ④ Windows 换行符处理（避免每次提交都一堆 CRLF 警告）
git config --global core.autocrlf true

# ⑤ 查看是否设置成功
git config --global --list
关于邮箱（重要）：GitHub 会把提交和账号关联，靠的就是这个邮箱。
如果不想暴露真实邮箱，用 GitHub 提供的匿名邮箱（在 GitHub → Settings → Emails 页面能看到）： 你的用户名@users.noreply.github.com
用错邮箱的后果：提交记录不显示在你的 GitHub 主页上，贡献图是空的，面试官看不出这些是你写的。

2. 日常四步（80% 的时间只用这四条）

# 1. 看现在什么情况（最常用，迷路了就敲它）
git status

# 2. 把改动放进暂存区
git add .                 # 全部改动
git add 文件名.html        # 只加某一个文件

# 3. 提交（拍快照，写清楚改了什么）
git commit -m "day6: 完成 localStorage 练习"

# 4. 看历史
git log --oneline         # 一行一条，简洁
git log --oneline --graph --all   # 带分支图
好的提交信息长什么样：说清"做了什么"，例如 day5: 完成原型链与 class 练习、修复待办列表刷新丢数据的问题。
别写 update、提交、1 这种——面试官真的会看提交记录。

3. 推到 GitHub（第一次要做的三步）

# ① 在 GitHub 网页上新建一个仓库（New repository），不要勾选 "Add a README"
#    假设仓库地址是 https://github.com/你的用户名/frontend-learning.git

# ② 在当前文件夹初始化，并关联远程仓库
cd D:\前端学习
git init
git remote add origin https://github.com/你的用户名/frontend-learning.git

# ③ 提交并推送（-u 记住关联，以后直接 git push 就行）
git add .
git commit -m "初始化：前端学习笔记"
git push -u origin main

# 之后日常只需要：
git add .
git commit -m "day7: 完成 Git 练习"
git push
第一次 push 会弹出浏览器让你登录 GitHub 并授权（Git for Windows 自带的凭据管理器）， 点授权就行，以后不用再输密码。
如果没弹窗、提示要用户名密码：GitHub 已经不支持密码推送，需要去 GitHub → Settings → Developer settings → Personal access tokens 生成一个 token，当密码用。

4. 分支与合并

# 看有哪些分支（* 号是当前所在分支）
git branch

# 新建分支并切过去（-c = create）
git switch -c feature-git-practice

# 在分支上正常改代码、add、commit……

# 切回主分支
git switch main

# 把分支合并进 main
git merge feature-git-practice

# 合并完可以删掉分支
git branch -d feature-git-practice

# 把分支推到 GitHub
git push -u origin feature-git-practice
老教程里用的是 git checkout，新写法是 git switch（切分支）和 git restore（恢复文件）。两个都能用，switch/restore 更不容易误操作。

5. 常见错误 & 救命命令

报错 / 情况原因解决
fatal: not a git repository 不在仓库目录里 cd 到有 .git 的目录，或先 git init
Please tell me who you are 没配 user.name / user.email 见第 1 节 ①
error: remote origin already exists 已经关联过 origin git remote set-url origin 新地址，或 git remote remove origin 再 add
rejected ... fetch first 远程有你本地没有的提交 先 git pull，解决冲突后再 git push
Support for password authentication was removed 用了密码推送 用浏览器授权 / 生成 Personal Access Token 当密码
提交写错信息了 — git commit --amend -m "新信息"（只能改最后一次）
刚 commit 就想撤销，但保留改动 — git reset --soft HEAD~1
改乱了想丢弃工作区的修改 — git restore 文件名（危险：改动会消失）
add 错了，想取消暂存 — git restore --staged 文件名
改到一半要切分支 — git stash 暂存起来 → 切过去 → git stash pop 恢复
fatal: invalid reference: main 初始分支叫 master，没有 main git branch -M main（改完再切）
PowerShell 里 git 的提示显示成红色，不代表报错。 git 把普通提示（如 Switched to branch 'main'、Auto-merging）写在 stderr 里， PowerShell 会把它标成红色错误块。只要没有 fatal: / error: 字样就不是出错。
另外：git merge 出现冲突时退出码是 1 —— 这是预期行为，不是程序崩了。

6. 冲突是什么样、怎么解决

两个分支改了**同一行**，Git 不知道听谁的，就让你自己决定。冲突文件里会出现这些标记：

<<<<<<< HEAD
这里是我当前分支（main）的内容
=======
这里是另一个分支（feature）的内容
>>>>>>> feature

解决三步：

# ① 打开文件，把 <<<、===、>>> 这些标记删掉，留下你想要的内容（可以两边都要）

# ② 告诉 Git 已经处理好了
git add 冲突的文件

# ③ 完成这次合并
git commit -m "合并 feature 分支，解决冲突"
冲突不是错误，是 Git 在向你求助"这里该用哪个"。遇到它不要慌，删标记、留内容、add、commit 就完事。

7. 今天要记住的最小集合

git status # 我在哪、有什么改动 git add . # 挑出要提交的 git commit -m "说明" # 拍快照 git push # 传到 GitHub git pull # 从 GitHub 拉最新 git log --oneline # 看历史 git switch -c 分支名 # 开分支 git merge 分支名 # 合并
