## 任务 1：修正你的 Git 身份 ⚠️ 最重要

**当前状态**（我检查过你的机器）：

```
user.name  = 27422187
user.email = 27422187@gitlab.com     ← 这是 GitLab 的邮箱，不是 GitHub
```

**问题**：这样推送到 GitHub，提交记录**不会关联到你的 GitHub 账号**——主页贡献图是空的，面试官点开仓库也无法确认是你写的。等于白提交。

**做法**：

```powershell
git config --global user.name "你的GitHub用户名"
git config --global user.email "你的GitHub邮箱"

# 顺手把另外三项配好
git config --global init.defaultBranch main
git config --global core.quotepath false
git config --global core.autocrlf true

# 验证
git config --global --list
```

> **邮箱怎么选**：不想暴露真实邮箱的话，用 GitHub 的匿名邮箱。
> 打开 GitHub → 右上头像 → Settings → Emails，能找到形如
> `12345678+你的用户名@users.noreply.github.com` 的地址，用它既能关联账号又不泄露邮箱。
> **如果你还没有 GitHub 账号，先去 github.com 注册一个**（用学校邮箱或个人邮箱都行）。

- [ ] 已完成，`git config --global user.name` 和 `user.email` 显示的是我自己的信息

## 任务 2：初始化仓库

```powershell
cd D:\前端学习
git init

git status                       # 应该看到一堆红色的 "Untracked files"
git branch --show-current        # 确认当前分支名（应该是 main）
```

**⚠️ 如果上面显示的是 `master` 而不是 `main`**，先执行这一条再往下走：

```powershell
git branch -M main
```

> **为什么必须先确认**：`git config --global init.defaultBranch main` 只对**新建的仓库**生效。
> 如果这里还是 `master`，后面"切回 main 分支"的命令会报 `fatal: invalid reference: main`，
> 你的分支和冲突练习会直接失败。（这个坑我在测试时踩到了，所以写进来。）

> **PowerShell 里 git 的提示显示成红色，别慌**：像 `Switched to branch 'main'`、
> `Auto-merging` 这类**正常提示**也会被 PowerShell 标红（因为它走的是 stderr）。
> 只要输出里没有 `fatal:` 或 `error:` 字样，就不是报错。

- [ ] 已完成 `git init`
- [ ] `git status` 能看到红色的未跟踪文件列表
- [ ] `git branch --show-current` 显示 `main`（不是 master）

## 任务 8：分支 + 合并（顺利版）

```powershell
git switch -c practice-branch        # 新建并切到新分支

# 改一下 README.md，在最后加一行：- [x] 学会用 Git 分支了
git add README.md
git commit -m "practice: 在分支上添加一行"

git switch main                      # 切回主分支（这时你会看到那行"消失"了）
git merge practice-branch            # 合并进来（这时那行又出现了）
git branch -d practice-branch        # 删掉分支
git push                             # 推上去
```

**验证**：切回 main 的瞬间文件内容变了——这就是分支的意义：**同一份代码，可以有多个平行世界**。

- [ ] 完成了一次"新建分支 → 提交 → 切回 → 合并 → 删分支"
- [ ] 能说出 `git switch main` 后为什么那行"消失了"

## 任务 9：故意制造一次冲突，然后解决它（重要练习）

```powershell
# ① 确保在 main，且工作区干净
git switch main
git status

# ② 开一个分支，把 README.md 的第 1 行改掉（比如改成 "# 我的前端学习仓库A"），提交
git switch -c conflict-practice
# ...改文件...
git add README.md
git commit -m "conflict-practice: 改标题为 A"

# ③ 切回 main，把同一行改成另一种内容（比如 "# 我的前端学习仓库B"），提交
git switch main
# ...改文件...
git add README.md
git commit -m "main: 改标题为 B"

# ④ 合并 → 冲突出现！
git merge conflict-practice
```

**解决冲突**：

```powershell
git status          # 会显示 "Unmerged paths"（未合并的路径）

# 打开 README.md，会看到：
# <<<<<<< HEAD
# # 我的前端学习仓库B
# =======
# # 我的前端学习仓库A
# >>>>>>> conflict-practice
#
# 把 <<<<<<<  =======  >>>>>>> 这三行标记删掉，留下你想要的内容

git add README.md
git commit -m "解决冲突：合并 conflict-practice 分支"
git branch -d conflict-practice
git push
```

- [ ] 成功制造并解决了一次冲突
- [ ] `git log --oneline --graph` 能看到分支合并的痕迹
