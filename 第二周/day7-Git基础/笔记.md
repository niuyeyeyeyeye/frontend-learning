## 一、核心概念：四个区域

```
工作区  --add-->  暂存区  --commit-->  本地仓库  --push-->  远程仓库(GitHub)
```

- **工作区**：你正在编辑的文件
- **暂存区（stage/index）**：挑出来"这次要提交"的改动
- **本地仓库**：`.git` 目录，存着所有历史快照
- **远程仓库**：GitHub

**为什么要有暂存区？** 让你能**选择性提交**：改了 5 个文件，只提交相关的 2 个，历史才干净、回退才安全。

## 二、必须记住的命令（8 条）

```powershell
git status                  # 我在哪、有什么改动（迷路就敲它）
git add .                   # 把改动放进暂存区
git commit -m "说明"        # 提交（拍快照）
git push                    # 推到 GitHub
git pull                    # 从 GitHub 拉最新
git log --oneline --graph   # 看历史（带分支图）
git switch -c 分支名        # 新建并切换分支
git merge 分支名            # 合并分支
```

## 四、分支与合并

- 分支 = **平行世界**：可以在不影响 main 的情况下改东西
- 典型流程：`git switch -c feature-x` → 改 → commit → `git switch main` → `git merge feature-x`
- 真实工作流：**每个需求/修复开一个分支 → 提 PR → Review → 合并**（大厂标准流程）

## 五、冲突（不是错误，是 Git 在问你）

两个分支改了**同一行**时出现：

```
<<<<<<< HEAD
当前分支的内容
=======
另一个分支的内容
>>>>>>> 分支名
```

**解决三步**：删掉标记、留下想要的内容 → `git add 文件` → `git commit -m "解决冲突"`

## 六、救命命令

| 想干什么 | 命令 |
|---|---|
| 改最后一次提交信息 | `git commit --amend -m "新信息"` |
| 撤销最后一次提交但保留改动 | `git reset --soft HEAD~1` |
| 丢弃工作区修改（危险） | `git restore 文件名` |
| 取消暂存（add 错了） | `git restore --staged 文件名` |
| 改到一半要切分支 | `git stash` → 切走 → `git stash pop` |
| 看远程地址 | `git remote -v` |
| 改远程地址 | `git remote set-url origin 新地址` |

## 七、面试可能问的 Git 问题（先混个眼熟）

1. **`git merge` 和 `git rebase` 的区别？** merge 保留分叉历史（多一条合并提交）；rebase 把提交"搬"到目标分支后面，历史是一条直线，但会改写提交 hash（**共享分支上不要用 rebase**）
2. **`git reset` 和 `git revert` 的区别？** reset 是"回到某个提交"（改写历史，本地用）；revert 是"用一次新提交去抵消旧提交"（安全，已推送的用这个）
3. **`git pull` 和 `git fetch` 的区别？** fetch 只下载不合并；pull = fetch + merge
4. **`.gitignore` 有什么用？** 让 Git 忽略指定文件（`node_modules`、日志、密钥），**被忽略的文件不会被提交**
5. **工作区、暂存区、版本库的关系？** 见第一节
6. **冲突怎么解决？** 见第五节（三步）
