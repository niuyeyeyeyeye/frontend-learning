复杂度怎么算（大 O 记法入门）

读完这一份，你就能给任何一段代码估出时间和空间复杂度。打开控制台看第 6 节的实测数据。

0. 先纠正一个误解

复杂度不是测"跑了几秒"，而是回答一个问题：

当数据量 n 变大时，操作次数增长得有多快？

为什么不用秒数衡量？两个原因：

  1. 同一段代码在你的电脑和服务器上跑，秒数不一样
  2. 数据小的时候，O(n²) 和 O(n) 看起来一样快；数据一大就差出几万倍（第 6 节有实测）

所以我们数的是"**操作次数**"，用字母 n 表示数据量，写成 O(某个关于 n 的式子)。

1. 算复杂度的三条规则（能解决 90% 的题）

规则 1：只看最大项，把小的丢掉
3n² + 5n + 7 → O(n²)
因为 n 很大时，n² 远远压过 5n 和 7。比如 n=1000：3n²=300万，5n=5000，7 可以忽略。
规则 2：忽略常数系数
2n → O(n)；n/2 → O(n)；100n → O(n)
因为常数在 n 变大时不起决定作用。3 步和 300 步都是"随着 n 线性增长"。
规则 3：默认说的是"最坏情况"
"在数组里找某个数"——最好情况第一个就找到（1 次），最坏要看完整个数组（n 次）。
我们说 O(n)。面试除非特别问，都答最坏情况。

2. 怎么数：只有两种动作 —— 相加 和 相乘

代码形态怎么算例子
顺序执行的几段代码 相加，然后取最大的那个 先 O(n) 再 O(n²) → O(n + n²) = O(n²)
循环包着一段代码 相乘：循环次数 × 循环体的复杂度 for (n 次) 内部做 O(1) → n × 1 = O(n)
嵌套循环 相乘：外层次数 × 内层次数 两层都跑 n 次 → n × n = O(n²)
实操口诀（照着做就行）：
① 找到执行次数最多的那一行代码
② 数它在最坏情况下执行多少次
③ 用 n 表示这个次数，去掉常数和系数

4. 实战：用你自己做过的两道题推一遍

例 1：两数之和 · 暴力解 → O(n²)

function twoSum(nums, target) {
  for (let i = 0; i < nums.length; i++) {          // 跑 n 次
    for (let j = i + 1; j < nums.length; j++) {    // 里面再跑约 n 次
      if (nums[i] + nums[j] === target) {          // ← 这行是执行最多的
        return [i, j]
      }
    }
  }
}

数法：内层那行执行 n × n ÷ 2 次 → 去掉常数 ½ → 时间 O(n²)，空间 O(1)（只用了 i、j 两个变量）。

例 2：两数之和 · Map 版 → O(n)

function twoSum(nums, target) {
  const map = new Map()                      // 额外开了一个 Map
  for (let i = 0; i < nums.length; i++) {    // 跑 n 次（只有一层！）
    const need = target - nums[i]
    if (map.has(need)) return [map.get(need), i]   // Map 查表是 O(1)
    map.set(nums[i], i)
  }
}

数法：只有一层循环跑 n 次，里面全是 O(1) 的操作 → n × 1 = 时间 O(n)。

空间：那个 Map 最坏要存 n 个元素 → 空间 O(n)（这就是「用空间换时间」）。

你笔记里两数之和写的是「时间 O(n) / 空间 O(?)」——那个问号填 O(n)。

例 3：字母异位词分组 → O(n·k log k)

function groupAnagrams(strs) {
  const map = new Map()
  for (const s of strs) {              // 外层：n 个字符串
    const key = s.split('').sort().join('')   // 关键：排序！这步不是 O(1)
    if (!map.has(key)) map.set(key, [])
    map.get(key).push(s)
  }
  return [...map.values()]
}

数法：这里有两个变量，别只盯着 n：

  • n = 字符串的个数
  • k = 单个字符串的长度
  • 外层跑 n 次；每次对长度 k 的字符串排序 → k log k
  • 所以：n × (k log k) = 时间 O(n·k log k)，空间 O(n·k)（要存下所有字符）
这是最容易漏的一点：循环体里如果做了"非 O(1)"的事，必须乘进去。 排序、includes、slice、字符串拼接，都不是 O(1)。

5. 空间复杂度怎么数

只数"你额外申请的内存"，不算输入本身。

情况空间
只用几个变量（i、sum、max…）O(1) —— 叫"原地操作"
新建了一个长度 n 的数组 / 存 n 个元素的 MapO(n)
新建了 n×k 的结构（比如二维数组）O(n·k)
递归函数至少 O(递归深度)，因为调用栈占内存
面试时如果答案"用空间换时间"（像两数之和的 Map 版），主动说出来，面试官会觉得你懂权衡。

7. 练习（先自己判断，再点开答案）

练习 1：求数组所有元素的和（一层 for）

看答案

时间 O(n)（遍历一次），空间 O(1)（只用了一个 total 变量）。

练习 2：判断数组里有没有重复元素（双层 for 两两比较）

看答案

时间 O(n²)（n×n），空间 O(1)。
优化思路：用 Set 边遍历边查 → 时间 O(n)，空间 O(n)。

练习 3：把一个数字数组从大到小排序（用内置 sort）

看答案

时间 O(n log n)（内置排序的复杂度），空间 O(log n) 左右（引擎实现不同，答 O(1)~O(log n) 都能接受，重点是说对 n log n）。

练习 4：在一段"从头到尾每次砍一半"的循环里执行 O(1) 操作（比如二分查找）

看答案

时间 O(log n)。因为 n 每次除以 2，直到 1，需要 log₂n 次。

练习 5：遍历数组，对每个元素都排序一次整个数组

看答案

时间 O(n² log n)（n 次 × 每次 n log n）。这种写法要警惕：循环体里的操作复杂度要乘进去。

练习 6（回到你的题）：字母异位词分组里，如果不用排序，改用"统计 26 个字母出现次数"当 key，复杂度是多少？

看答案

时间 O(n·k)（每个字符串扫一遍统计，是 k 不是 k log k），比排序版 O(n·k log k) 更快。
想通了这一点，你就掌握了"优化复杂度"的思路：找出最贵的那一步，换掉它。

8. 面试话术模板（照这个说）

"我用一个 Map 存「值 → 下标」，只遍历一次数组，每个元素做一次 O(1) 的哈希查找， 所以时间复杂是 O(n)；额外开了一个最多存 n 个元素的 Map，所以空间是 O(n)。 比暴力双层循环的 O(n²) 快，代价是多花了 O(n) 的空间。"

要点：① 说清用了什么结构 ② 说清循环几层 ③ 说清额外空间 ④ 说清取舍。
