超时了怎么办（TLE 处理方案）

LeetCode 报 Time Limit Exceeded（超出时间限制） 时看这一篇。先打开控制台，第 5 节有可运行的实测。

1. TLE 到底是什么

TLE = 你的算法跑得太慢，超过了平台的限制（力扣多数题目约 1~2 秒）。
它不是"代码写得慢"，而是"算法的时间复杂度太高"。
  • 它和"答案错误（Wrong Answer）"不同：**你的逻辑多半是对的，只是不够快**
  • 所以 TLE 是**最有指导性的报错**——它直接告诉你"复杂度这一关没过"
  • 真实面试里**不会给你 TLE**：面试官会直接问"你这个解法的时间复杂度是多少？"——所以现在把 TLE 当成免费的复杂度检测器

2. ⭐ 核心技能：用数据量反推复杂度上限

这是最实用的一招：**先看题目给的 n 有多大，就知道该用什么复杂度的算法**。看题时就能判断，不用等 TLE。

题目给的 n 范围允许的复杂度该想到的算法
n ≤ 10O(n!) / O(2ⁿ)全排列、暴力穷举
n ≤ 100O(n³)三重循环
n ≤ 1000O(n²)双层循环、简单 DP
n ≤ 10⁵O(n log n)排序、二分、堆
n ≤ 10⁶ ~ 10⁷O(n)哈希表、双指针、滑动窗口、前缀和
n 更大O(log n) / O(1)数学公式、二分
怎么用：题目说 1 ≤ nums.length ≤ 10⁵，你就该立刻排除 O(n²) —— 因为 10⁵ × 10⁵ = 10¹⁰ 次操作，JS 一秒只能做约 10⁷~10⁸ 次，必然超时。
10⁵ 这个数量级 → 只能用 O(n) 或 O(n log n)。

3. 定位问题：四步法

  1. 看 TLE 出现在哪个用例
    力扣会显示"最后执行的输入"，看那个数组/字符串有多长 → 用上面的表反推允许的复杂度
  2. 找你代码里的"执行次数最多的那一行"
    就是你 Day1 学的"数操作次数"：哪一层循环最内层、哪个操作被反复执行
  3. 用优化模式替换它
    见第 6 节的对照表（哈希表、双指针、前缀和、记忆化…）
  4. 不要做常数级微优化
    把 for 改成 while、let 改成 const、 删掉几个变量 —— 这些改变不了数量级，救不了 TLE

4. JS 特有的坑：这些操作"看着是 O(1)，其实很贵"

很多 TLE 不是因为双层循环，而是**循环里藏了一个 O(n) 的操作**。这是 JS 新手最容易踩的：

操作真实复杂度后果
arr.includes(x) / arr.indexOf(x) 在循环里O(n)整体从 O(n) 变成 O(n²) ⚠️
arr.shift() / arr.unshift()O(n)要移动整个数组；队列请用索引或双指针
arr.slice() / arr.splice()（非末尾）O(n)每次都复制/移动元素
循环里 str += x 拼接字符串O(n) 每次整体 O(n²)；改用数组 join
arr.sort() 在循环里O(n log n) 每次整体变成 O(n² log n)
Set.has() / Map.get()✅ O(1)这才是对的选择
循环里大量 console.log很慢提交前一定要删掉调试输出
最容易上钩的写法：if (arr.indexOf(arr[i]) !== i) ... —— 看起来只有一层循环（O(n)），但 indexOf 本身是 O(n)，合起来还是 O(n²)。 把它换成 Set 就变成真正的 O(n)。

6. 优化模式对照表（找到瓶颈后照这张表换）

瓶颈换成什么复杂度变化
反复查找"某个值在不在"Set / Map / 对象O(n) → O(1)
两层循环找配对哈希表（存"值→下标"）O(n²) → O(n)
两层循环枚举子数组/子串双指针 / 滑动窗口O(n²) → O(n)
反复求区间和前缀和每次 O(n) → O(1)
需要排序后才能用双指针先排序（O(n log n)）用一次排序换后面全变简单
递归重复计算记忆化 / 动态规划O(2ⁿ) → O(n)
找"下一个更大/更小元素"单调栈O(n²) → O(n)

7. 本地计时调试（力扣上是黑盒，本地能秒定位）

// 用大数据量测你的函数，看哪一步慢
const big = Array.from({ length: 100000 }, () => Math.floor(Math.random() * 100000))

let t = performance.now()
你的函数(big)
console.log('耗时：', (performance.now() - t).toFixed(1), 'ms')
// 超过 1000ms 基本就会 TLE（力扣限制约 1~2 秒）

技巧：**把 n 翻倍看耗时变化** ——如果耗时翻 4 倍，说明是 O(n²)；翻 2 倍是 O(n)；几乎不变是 O(log n) 或 O(1)。

8. 自查清单（提交前 10 秒过一遍）

  • ⬜ 题目给的 n 上限是多少？我算法的复杂度符合第 2 节的表吗？
  • ⬜ 循环里有没有 includes / indexOf / slice / shift / 字符串 +=？
  • ⬜ 有没有在循环里做排序？
  • ⬜ 递归有没有重复计算（该记忆化了吗）？
  • ⬜ 有没有死循环？（循环变量真的在变吗）
  • ⬜ 调试用的 console.log 删干净了吗？

9. 心态提醒

TLE 在学习阶段是好消息。
它精确地告诉你"思路对但复杂度不对"，比"答案错误"更容易修 —— 因为优化方向是有限的（第 6 节那 7 种），而逻辑错误有无数种。
