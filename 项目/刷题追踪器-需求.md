# 刷题账本（项目需求 · v0.2）

> 2026-11-23 起草 / 11-23 定稿
> 代号：**刷题账本**　域名建议：`shuati-ledger.vercel.app`
>
> **一句话定位**：记录每道题的思路和踩过的坑，按专题/难度/复习轮次管理，
> 并告诉你「今天该复习哪几道题」+「我反复在犯哪一类错」。

---

## 一、为什么做这个（面试必答）

LeetCode 记的是**提交结果**，但面试考的是**能不能独立写出来**。所以我需要记三件 LeetCode 不记的事：

| 要记的 | 为什么 |
|---|---|
| 这次是**独立 AC** / 看提示 / 没写出来 | 决定这题算不算“会了” |
| 当时**错在哪**，而且**属于哪一类错** | 我反复犯同一类错（越界/空值出现 7 次） |
| **第几轮**复习、下次什么时候 | 三轮制：第一遍“见过”，第二遍“会做”，第三遍“能讲” |

**为什么不直接用 Notion / 飞书表格**：
1. 表格每次要填 6 个字段，太慢 → 我要“一键记一次练习”
2. 真正的查询是「今天该复习哪些链表题」= 上次练习时间 + 轮次算出来的 → 表格做不到
3. 我要一眼看到「**我这个月又有 5 次栽在越界/空值上**」→ 表格要靠人肉统计

**已有数据**：`算法/算法笔记.md` 里有 34 道题的完整记录，可以直接录入。

## 二、数据模型（2 张表）

> 设计原则：**能用算的，就不要存**（DAY10 学的「派生数据」）。

```prisma
// 题目
model Problem {
  id         Int      @id @default(autoincrement())
  leetcodeId Int?     // 力扣题号（自编题可以为空）
  title      String
  difficulty String   // 简单 / 中等 / 困难
  topic      String   // 数组 / 哈希 / 双指针 / 链表 / 树 / DP ...
  status     String   // new 未做 / seen 见过🟡 / mastered 会做🟢
  note       String?  // 思路
  pitfall    String?  // 这道题最关键的坑（自由文本）
  createdAt  DateTime @default(now())

  attempts   Attempt[]

  @@unique([leetcodeId])
}

// 每次练习记录（一道题多条）
model Attempt {
  id          Int      @id @default(autoincrement())
  problemId   Int
  date        DateTime @default(now())
  durationMin Int?     // 这次花了多久
  result      String   // ac 独立写出 / hint 看了提示 / fail 没写出来
  round       Int      @default(1)  // 第几轮（1/2/3）
  memo        String?  // 这次具体错在哪（自由文本）
  pitfallTag  String?  // ⭐ 错误类型（枚举，可聚合统计）
  problem     Problem  @relation(fields: [problemId], references: [id], onDelete: Cascade)
}
```

### ⭐ 关键设计：为什么要有 `pitfallTag`

`memo` 是**自由文本**（“指针为空取 val 报错”），人看得很清楚，但**机器没法聚合**。

所以要再加一个**枚举标签**，把自由文本归到有限几类：

```ts
const PITFALL_TAGS = [
  { value: 'boundary', label: '越界 / 空值' },   // 你犯了 7 次
  { value: 'js',       label: 'JS 细节' },       // sort 比较函数、charCodeAt…
  { value: 'pointer',  label: '指针 / 作用域' },
  { value: 'logic',    label: '思路错' },
  { value: 'other',    label: '其他' },
] as const
```

**这条能讲的东西很多**（面试加分）：
> “自由文本和可聚合标签要分开存。只存文本就没法统计，只存标签就丢了细节。”

聚合查询就是一行：

```ts
await prisma.attempt.groupBy({
  by: ['pitfallTag'],
  where: { pitfallTag: { not: null } },
  _count: { _all: true },
  orderBy: { _count: { pitfallTag: 'desc' } },
})
// → [{ pitfallTag: 'boundary', _count: { _all: 7 } }, ...]
```

### 派生数据（不建表、不存字段）

| 要显示的 | 怎么算 |
|---|---|
| **下次复习日** | 最后一次 attempt 的 `date` + 3 天 |
| **今天该复习** | `下次复习日 <= 今天` 且 `round < 3` |
| **掌握度** | 最近一次 `result === 'ac'` 且 `round >= 2` → 算“会做” |
| **连续打卡天数** | 从今天往前数，每天至少 1 条 attempt |

## 三、MVP（7 项，一周内能做完）

| # | 功能 | 用到的技术 |
|---|---|---|
| 1 | 题目列表 + **筛选**（专题/难度/状态）+ 排序 | Server Component 取数；筛选条件放 **URL** |
| 2 | 新增 / 编辑题目（含思路、踩的坑） | Server Action 或 API 路由 + zod 校验 |
| 3 | **一键记一次练习**（选结果 + 耗时 + **错误类型**） | Client Component + **乐观更新** |
| 4 | 题目详情：该题的历史练习记录 | 动态路由 `[id]` |
| 5 | **今日待复习**（首页） | 聚合查询 |
| 6 | ⭐ **错误类型统计**（我反复栽在哪一类） | Prisma `groupBy` + CSS 条形图 |
| 7 | 登录 + 数据隔离 | ⏸ **最后一天做，做不出就发单用户版** |

### 明确不做

❌ 社交 / 分享 / 排行榜 ❌ 多人协作 ❌ 实时同步 ❌ 移动 App ❌ 图表库

```prisma

  provider = "prisma-client-js"
```

