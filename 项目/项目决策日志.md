## 1. 选题：为什么做"刷题账本"

**现象**：LeetCode 只有提交记录，不记"我是独立写出来的还是看答案的"，也没有多轮复习追踪。我的错题散在 `算法笔记.md` 里，靠人肉统计。

**判断**：这个需求我每天在用，而且笔记里已有 34 道题的完整记录 —— 项目上线第一天就有内容，不是空壳。

**结果**：定位是"记录思路和踩过的坑 + 算出今天该复习哪几题"。

**面试可以怎么说**：
> "LeetCode 记的是提交结果，但面试考的是能不能独立写出来。所以我做了个追踪器，核心不是存题，是算'今天该复习哪几道'。"

## 2. 数据库：从 SQLite 改成 Postgres

**现象**：最初用 SQLite（`file:./dev.db`），本地建表成功。

**判断**：Vercel 是 serverless，文件系统是**临时的**，SQLite 文件不会被持久化 → 部署后数据会丢。所以必须换云数据库。

**结果**：改用 Neon 托管的 Postgres（免费额度够用），本地和线上同一套库，省掉"部署时切库"这一步。

**面试可以怎么说**：
> "serverless 平台的本地文件不持久，所以文件型数据库不适合部署场景，我换成了托管的 Postgres。"

## 3. 原生模块编译失败：从 better-sqlite3 改用 pg

**现象**：`npm i @prisma/adapter-better-sqlite3` 失败：

```
prebuild-install warn install read ECONNRESET
gyp ERR! find VS  You need to install the latest version of Visual Studio
```

**判断**：`better-sqlite3` 是原生模块 —— 它的预编译二进制要从 GitHub Releases 下载（被网络重置），失败后退化成用 node-gyp 从源码编译，而源码编译需要 Visual Studio C++ 工具链（没装）。

**结论**：选**纯 JS** 的驱动 `pg`（配合 `@prisma/adapter-pg`），彻底避开原生编译。

**面试可以怎么说**：
> "原生模块依赖平台二进制，安装链路容易断（下载失败→源码编译→缺编译器）。服务端项目我优先选纯 JS 依赖，跨环境更可靠。"

## 4. Prisma 版本：`latest` 指向的是 RC

**现象**：`npm i -D prisma` 装到了 **8.0.0-rc.34**，而 `@prisma/client` 是 **7.10.1** —— CLI 和 client 大版本不一致。而且 Prisma 8 的 `orm init` 只支持 postgres/mongodb，**没有 sqlite**。

**判断**：查 `npm view prisma dist-tags` 发现 `latest` 挂在 RC 上，`prev` 才是稳定的 7.10.1。

**结论**：`npm i -D prisma@7.10.1`，让 CLI 和 client 版本对齐。

**面试可以怎么说**：
> "装依赖前我会看 dist-tags。那次 `latest` 指向 RC，导致 CLI 与 client 大版本不一致，我 pin 到稳定版解决。生产项目里盲目用 latest 是个坑。"

## 5. Prisma 7 的新架构：必须自己提供 driver adapter

**现象**：`prisma -v` 显示 `Query Compiler : enabled`；生成的客户端类型里写着：

```ts
type PrismaClientOptions = PrismaClientOptionsWithAccelerateUrl | PrismaClientOptionsWithAdapter
// 前者 adapter?: never，后者 adapter: SqlDriverAdapterFactory（必填）
```

**判断**：Prisma 7 不再用 Rust 的 query engine 二进制，改成 Query Compiler + driver adapter —— 所以必须显式传 `adapter`。

**结果**：`new PrismaClient({ adapter: new PrismaPg(process.env.DATABASE_URL) })`。

**面试可以怎么说**：
> "Prisma 7 换了执行引擎架构，连接数据库变成由我提供的 driver adapter 负责，这带来了更小的体积和更快的冷启动。"

## 6. 数据模型：三个关键决策

### ① 主键 `id` 与业务标识 `leetcodeId` 分离

- `id Int @id @default(autoincrement())` —— 数据库行号，自动生成
- `leetcodeId Int? @unique` —— 力扣题号，**可空**（面试手写题、自选题没有题号）

**理由**：主键不能为空，而业务标识可能缺失，两者必须分开。

### ② `memo`（自由文本）与 `pitfallTag`（枚举）分离

- `memo String?` —— "指针为空取 val 报错"，人能看懂
- `pitfallTag String?` —— `boundary / js / pointer / logic / other`，**机器能聚合**

**理由**：只存文本没法统计，只存标签丢了细节。

聚合就一行：
```ts
prisma.attempt.groupBy({ by: ['pitfallTag'], _count: { _all: true } })
```

### ③ 复习轮次不单独建表

"下次复习日" = 最后一次练习日期 + 3 天，**每次算出来**。

**理由**：存字段就要手动同步，漏一处就不一致。能算的不存。

**面试可以怎么说**：
> "派生数据不落库。我本来可以加 `nextReviewDate` 字段，但那样每次写练习都要手工维护，容易出现不一致；改成查询时计算，代价可控且不会错。"

## 7. Server / Client 边界：`'use server'` 漏了会怎样

**现象**：构建报错

```
You're importing a module that depends on "revalidatePath" into a React Client Component module
```

**判断**：`actions.ts` 忘了写 `'use server'`，于是被导入它的 `AttemptForm.tsx`（`'use client'`）"传染"成客户端模块，而 `next/cache` 只能在服务端用。

**结论**：`'use server'` / `'use client'` 必须在文件**第一行**。

**顺带**：Server Action 写完数据库要调 `revalidatePath()`，否则页面还是旧数据。

**面试可以怎么说**：
> "Next 的 App Router 里指令是文件级的，谁的导入链上有 `'use client'` 就会被当客户端模块。所以 'use server' 必须写在自己文件的第一行。"

## 8. Next 16 Cache Components 导致构建失败（本地正常，线上挂）

**现象**：本地 `npm run dev` 一切正常，Vercel 构建报错：

```
Error: Route "/problems": Next.js encountered uncached or runtime data during prerendering.
`searchParams` accessed outside of `<Suspense>` prevents the route from being prerendered
```

**判断**：`next.config.ts` 里开着 `cacheComponents: true` / `partialPrefetching: true`。Next 16 的 Cache Components 要求动态数据（`searchParams` / `params` / DB）必须包在 `<Suspense>` 里，否则构建期预渲染会失败 —— **而 dev 模式不做预渲染，所以本地看不出来**。

**结论**：这个项目的所有页面都依赖数据库，本来就无法预渲染，所以关掉这两个开关；正确的长线做法是用 `<Suspense>` 包住数据访问，换取流式渲染。

**面试可以怎么说**：
> "遇到'本地能跑、部署就挂'，我先看构建日志里 `Generating static pages` 那几行 —— 结果是预渲染时读到了运行时数据。根因是 Cache Components 要求动态数据必须在 Suspense 边界内，而 dev 不预渲染所以复现不了。"

## 9. 筛选状态放在 URL，不放 useState

**实现**：`/problems?topic=链表&difficulty=简单`，Server Component 读 `searchParams`（Next 15+ 是 Promise，要 `await`）。

**理由**：
- 刷新不丢
- 能分享链接
- 能后退
- 服务端直接拿条件查库，不需要客户端再发请求

**踩到的细节**：`searchParams` 的值类型是 `string | string[] | undefined`（同名参数出现多次就是数组），所以要做类型收窄：

```ts
const topic = typeof sp.topic === 'string' ? sp.topic : undefined
```

**多选的"再点一次取消"**：
```ts
if (current[key] !== value) next.set(key, value)   // 已选中就不加 → 等于取消
```

## 10. 部署：`*.vercel.app` 在国内被 DNS 污染

**现象**：挂 VPN 能打开，直连超时。

**实测数据**：
```
shuati-ledger-j52e.vercel.app 的 DNS  → 202.160.129.37（不是 Vercel 的 IP）
Vercel 真实 IP 66.33.60.34:443        → 通，69ms
github.com:443                        → 通，104ms
```

**判断**：不是 IP 被封，是 **DNS 被污染**（返回假 IP）。所以绑定自己的域名、CNAME 到 `cname-china.vercel-dns.com`（中国优化线路）可以绕开。

**兜底**：README 放截图 + 演示 GIF，保证"链接打不开也能看"。

**面试可以怎么说**：
> "域名打不开要先分清是 DNS 污染还是 IP 被封 —— 我实测真实 IP 是通的，只是 DNS 返回了假地址，所以换自定义域名 + CNAME 就解决了。"
