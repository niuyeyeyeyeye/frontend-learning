## 一、全貌：一条完整链路

```
① create-next-app          建骨架（Next + TS + CSS Modules）
         ↓
② npm i prisma             装「建表工具」（CLI，只在开发时用）
   npm i @prisma/client    装「查库工具」（运行时客户端）
   npm i @prisma/adapter-pg 装「Postgres 驱动适配器」
         ↓
③ prisma init              生成 3 个文件：schema.prisma / prisma7.config.ts / .env
         ↓
④ 写 model                 描述「表长什么样」（Problem / Attempt）
         ↓
⑤ prisma migrate dev       把 model 变成真实建表 SQL，并在数据库执行
         ↓
⑥ prisma generate          根据 model 生成「带类型提示的查询代码」→ src/generated
         ↓
⑦ src/lib/prisma.ts        创建连接池单例 + 贴上 Postgres 驱动
         ↓
⑧ app/problems/page.tsx    Server Component 里 await 查询 → 渲染 HTML
```

## 二、逐层拆解

### ① 项目骨架层

| 命令 | 作用 | 少了会怎样 |
|---|---|---|
| `npx create-next-app@latest shuati-ledger --typescript --app --src-dir --no-tailwind --eslint` | 生成 Next 项目骨架 | 你得手动装 Next/TS/ESLint 并配 20 个配置文件 |

这一步选定了三件事：

| 选项 | 结果 |
|---|---|
| `--app` | 用 **App Router**（`app/` 目录即路由）|
| `--typescript` | 用 TS |
| `--no-tailwind` | 样式用 **CSS Modules**（`xxx.module.css`）|

---

### ② 依赖层（四个包，职责完全不同）

| 包 | 是什么 | 放在哪 | 少了会怎样 |
|---|---|---|---|
| `prisma` | **CLI 工具**：`init` / `migrate` / `generate` / `studio` | devDependencies | 没法建表、没法生成客户端（**只在开发时用**）|
| `@prisma/client` | **运行时库**：程序查库用的代码 | dependencies | 页面里没法 `await prisma.problem.findMany()` |
| `@prisma/adapter-pg` | **驱动适配器**：告诉 Prisma「怎么连 Postgres」 | dependencies | Prisma 7 里**必填**，不装就启动报错 |
| `dotenv` | 读 `.env` 文件 | devDependencies | Prisma 7 的配置文件用它读 `DATABASE_URL` |

> **面试点**：`dependencies` vs `devDependencies`
> CLI 只在开发时用 → dev；客户端代码要跑在线上 → dependencies。

**Prisma 7 的关键变化**：查询不再用 Rust 的 query engine 二进制，改成 **Query Compiler + driver adapter**。
所以必须自己指定 adapter（`@prisma/adapter-pg`），`prisma -v` 里那句 `Query Compiler : enabled` 就是在提示这个。

---

### ③ 配置层（3 个文件，各管一件事）

| 文件 | 内容 | 作用 | 少了会怎样 |
|---|---|---|---|
| `prisma/schema.prisma` | `generator`（生成什么）+ `datasource`（用什么数据库）+ `model`（表结构） | **唯一的真相来源** | 没模型就没表 |
| `prisma7.config.ts` | schema 路径、migrations 路径、**数据库 URL 怎么取** | Prisma 7 新增的入口配置 | CLI 不知道连哪个库 |
| `.env` | `DATABASE_URL="postgresql://..."` | 存**连接串**（含密码） | 不知道连哪个库；写进代码则密码泄露 |

**Prisma 7 的变化**：`datasource` 块里**不再写 `url`**，url 挪到了 `prisma7.config.ts`：

```prisma
datasource db {
  provider = "postgresql"    // 只有 provider，没有 url
}
```

```ts
// prisma7.config.ts
import "dotenv/config";      // ← 靠这行读 .env
export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: { path: "prisma/migrations" },
  datasource: { url: process.env["DATABASE_URL"] },
});
```

---

### ④ 迁移层（`prisma migrate dev`）

它做的三件事：

| 步骤 | 作用 |
|---|---|
| 1. 读 schema，对比数据库现状 | 算出「要建/改哪些表」 |
| 2. 生成 `prisma/migrations/时间戳_init/migration.sql` | **把变更写成 SQL 文件并归档**（可进 git、可回滚、可重现）|
| 3. 在数据库执行这个 SQL | 真正建表 |

**少了 `migrations/` 目录会怎样**：
你就是「手动改数据库」—— 改了什么没人知道，团队没法同步，线上也没法重现。
**迁移文件 = 数据库的版本控制。**

> 踩过的坑：SQLite 生成的迁移是 `AUTOINCREMENT` 方言，切换 Postgres 时必须**删掉整个 `prisma/migrations/` 重新生成**，否则 SQL 执行失败。

---

### ⑤ 客户端生成层（`prisma generate`）

| 它做的 | 作用 |
|---|---|
| 读 schema，在 `src/generated/prisma/` 生成 TS 代码 | 让 `prisma.problem.findMany()` **有类型提示，字段写错编译期就报** |

**Prisma 7 里 `migrate dev` 不会自动 generate**，必须单独跑一次。

**少了它会怎样**：`prisma.problem` 是 undefined → 页面报 `Cannot read properties of undefined (reading 'findMany')`。

**入口文件是 `client.ts`，不是目录导入**：

```ts
import { PrismaClient } from '@/generated/prisma/client'   // ✅
import { PrismaClient } from '@/generated/prisma'         // ❌ 没有 index.ts
```

| 文件 | 用途 |
|---|---|
| `client.ts` | ⭐ 服务端用（完整客户端，能连数据库）|
| `browser.ts` | 客户端组件用的类型（不含驱动，**不能真查库**）|

---

### ⑥ 运行时层（`src/lib/prisma.ts`）

```ts
import { PrismaPg } from '@prisma/adapter-pg'
import { PrismaClient } from '@/generated/prisma/client'

const globalForPrisma = globalThis as unknown as { prisma?: PrismaClient }

export const prisma =
  globalForPrisma.prisma ??
  new PrismaClient({ adapter: new PrismaPg(process.env.DATABASE_URL as string) })

if (process.env.NODE_ENV !== 'production') {
  globalForPrisma.prisma = prisma
}
```

三件事：

| 这 3 行在解决什么 | 说明 |
|---|---|
| **创建客户端** | 它内部维护一个**连接池**（不是每次查询都新建连接）|
| **贴 adapter** | 告诉它「用 pg 驱动连 Postgres」|
| **挂到 `globalThis`** | dev 热更新会重复执行模块顶层代码 → 不挂就会创建成百上千个连接池 → **数据库连接数打满** |

**少了 `globalThis` 那段会怎样**：改几次代码后 Neon 上出现几十个活动连接，最后报 `too many connections`。

---

### ⑦ 应用层（`app/problems/page.tsx`）

```tsx
export default async function ProblemsPage({ searchParams }: Props) {
  const sp = await searchParams
  const problems = await prisma.problem.findMany({
    where: { topic: sp.topic },
    orderBy: { createdAt: 'desc' },
    include: { _count: { select: { attempts: true } } },
  })
  return <div>{problems.map(...)}</div>
}
```

| 关键点 | 作用 |
|---|---|
| `async` 组件 | 它是 **Server Component**，在服务器上执行 |
| 直接 `await` 查询 | **不需要** useEffect + axios + loading 三态 |
| 文件位置决定路由 | `app/problems/page.tsx` → `/problems` |
| `searchParams` 是 **Promise** | Next 15+ 要 `await`，不是客户端那个 `useSearchParams` |

**Server vs Client 的判断规则**：

```
要取数据（数据库/文件/密钥）  → Server Component（默认，不写任何指令）
要交互（useState/onClick/useEffect）→ 加 'use client'
```

⚠️ **`src/lib/prisma.ts` 不能从 `'use client'` 组件里 import** —— 否则会把 node 模块打进浏览器包。

## 四、标准操作流程（背下来）

### 场景 A：加一个字段

```powershell
# 1. 改 prisma/schema.prisma（加字段）
# 2. 生成迁移 + 执行
npx prisma migrate dev --name add_xxx_field
# 3. 重新生成客户端
npx prisma generate
# 4. 页面里就能用新字段了
```

### 场景 B：改数据模型（加表 / 改关系）

同上三步，只是 `--name` 换成有意义的描述（`add_tag_table`）。

### 场景 C：新加一个页面

```
新建 src/app/xxx/page.tsx  →  访问 /xxx
```
不需要改任何路由配置。

### 场景 D：新加一个交互组件（要用 useState）

新建文件，第一行写 `'use client'`，然后像普通 React 那样写。

## 五、排错对照表

| 报错 | 出问题的层 | 原因 | 解法 |
|---|---|---|---|
| `Cannot find module '@/generated/prisma'` | ⑤ | 目录导入，没有 index.ts | 改成 `@/generated/prisma/client` |
| `Cannot read properties of undefined (reading 'findMany')` | ⑤ / ⑥ | 客户端没生成，或模块缓存了旧版 | `npx prisma generate` + 重启 dev |
| `PrismaClientInitializationError` | ⑥ / ③ | 没传 adapter，或 `DATABASE_URL` 读不到 | 检查 adapter；重启 dev 重读 `.env` |
| `P1001: Can't reach database server` | ③ | 连接串错 / 网络不通 | 检查 URL；Neon 跨境偶尔抖动 |
| `client password must be a string` | ③ | `DATABASE_URL` 是 undefined | `.env` 没被读到，重启 dev |
| `PrismaClient is unable to run in this browser environment` | ⑦ | 在 `'use client'` 组件里 import 了 prisma | 把查询挪到 Server Component |
| `too many connections` | ⑥ | 没有 globalThis 单例 | 补上 `globalThis` 那段 |
| `P1013: must start with postgresql://` | ③ | 还在用旧的 `file:./dev.db` | 改 `.env` |
| 警告 `SSLMODE ... aliases for verify-full` | ③ | `sslmode=require` 语义要变 | 改 `sslmode=verify-full` |
| 依赖装到 RC 版（`8.0.0-rc`）| ② | `latest` 标签指向 RC | `npm view xxx dist-tags` 看版本，pin 稳定版 |

## 六、踩过的三个坑（面试素材）

| 坑 | 教训 | 可迁移的能力 |
|---|---|---|
| `prisma` 装到 **8.0.0-rc**，`@prisma/client` 是 7.10.1 → 版本不一致 | **`latest` 标签可能指向 RC**。装之前看 `npm view xxx dist-tags`，pin 到稳定版 | 依赖管理 |
| `better-sqlite3` 装不上：预编译包从 GitHub 下载被 `ECONNRESET` → 退化成 node-gyp 源码编译 → 没有 Visual Studio | **原生模块 vs 纯 JS** 的风险差异。`pg` 是纯 JS，永远不会踩这个坑 | 技术选型 |
| SQLite 建完表又切 Postgres | **文件数据库不能用在 serverless 上**（Vercel 文件系统是临时只读的）| 部署认知 |

---

## 七、能讲的 3 个技术点（面试用）

1. **Server Component 取数 vs 客户端 fetch**
   —— 为什么能直接在组件里 `await`？边界在哪？什么必须拆成 `'use client'`？

2. **URL 作为筛选状态源**
   —— 刷新不丢、能分享、能后退。Server Component 读 `searchParams`（Promise）而不是 `useSearchParams`。

3. **`memo`（自由文本）与 `pitfallTag`（枚举）分离**
   —— 只存文本没法聚合统计，只存标签丢了细节。聚合就一行 `groupBy`。
